## 1. 背景

### 为什么需要 Phase 2

DAIR.AI 提示词体系是经过验证的经典方法论，但它是 **2024 年以前基于 GPT-4/Claude 3 等非推理模型**建立的。

OpenAI 官方 2025-2026 指南（含 GPT-5 推理模型专项）带来了两个关键变化：

| 变化 | 影响 |
|------|------|
| 推理模型（GPT-5/o1/o3）内置思考链 | 手动 CoT 引导（"让我们一步步思考"）对推理模型可能适得其反 |
| 幻觉控制 / 系统化测试两大盲区 | DAIR.AI 体系完全没有覆盖，需要新增方法论 |

**Phase 2 的目标**：用 OpenAI 标准对 DAIR.AI 体系做「外科手术式」修正——保留核心，通过小修补齐盲区，不做全量重构。

## 2. 必须修正项 P0

> 影响最大、必须修正，否则模板在推理模型场景下表现退化或缺失关键能力。

### P0-1：增加幻觉控制机制（Reference Text）

| 项目 | 内容 |
|------|------|
| **问题** | DAIR.AI 体系完全没有处理模型「胡编乱造」的能力，这是最大的盲区 |
| **影响范围** | 所有涉及数据分析、事实查询、报告生成的模板 |
| **应修正文件** | `prompt-kb/02-text-prompts/templates/` 下所有涉及信息输出的模板；<br>`prompt-kb/03-methods/` 方法论文档 |
| **建议修改方式** | 在模板「上下文 / Context」区块增加标准防幻觉段落：<br>`### 参考资料`<br>`你只能基于以下信息回答...`<br>见校准文档 §12 修正 A |
| **是否影响 T-TEXT-001** | ✅ 已完成——T-TEXT-001 v0.3/v0.4 所有 prompt 模板均已内置参考资料区块 |
| **优先级** | ✅ **P0-1 已完成**（T-TEXT-001 v0.3 验收通过） |

### P0-2：补充分隔符规范

| 项目 | 内容 |
|------|------|
| **问题** | OpenAI P2 明确要求用 `###` 或 `"""` 分隔指令与上下文；DAIR.AI 模板普遍没有显式分隔符 |
| **影响范围** | 全部 7 个核心模板（T-TEXT-001 ~ T-TEXT-007） |
| **应修正文件** | `prompt-kb/02-text-prompts/templates/` 下所有模板 |
| **建议修改方式** | 在模板头部统一使用 `###` 分隔：<br>`### 指令` / `### 上下文` / `### 输入` / `### 输出要求`<br>简化版可用 `---` 分隔主要区块 |
| **是否影响 T-TEXT-001** | ✅ 已完成——T-TEXT-001 v0.3/v0.4 全部 prompt 模板已升级为 `###` 分隔符规范 |
| **优先级** | ✅ **P0-2 已完成**（T-TEXT-001 v0.3 验收通过） |

### P0-2b：统一待确认标记格式（补充）

| 项目 | 内容 |
|------|------|
| **问题** | v0.3 验收中发现 `【待确认】` 全角与 `[待确认]` 半角混用，可能导致 AI 标记理解歧义 |
| **影响范围** | T-TEXT-001 所有 prompt 模板 |
| **应修正文件** | `prompt-kb/02-text-prompts/templates/fuzzy-request-to-plan-pipeline.md` |
| **建议修改方式** | 统一替换 5 处 `【待确认】` → `[待确认]`，其余 7 处半角保持不变 |
| **是否影响 T-TEXT-001** | ✅ 已完成——T-TEXT-001 v0.4 全部替换为 `[待确认]` 半角标记 |
| **优先级** | ✅ **P0-2b 已完成**（T-TEXT-001 v0.4 验收通过）

### P0-3：增加模型类型判断机制

| 项目 | 内容 |
|------|------|
| **问题** | DAIR.AI CoT 对所有推理任务一视同仁；但 GPT-5/o1/o3 等推理模型内置思考链，手动引导多余 |
| **影响范围** | `prompt-kb/01-fundamentals/dair-ai-advanced-prompting.md`；<br>T-TEXT-001 进阶版 Step 1'/2' |
| **建议修改方式** | 在方法论文档中增加「模型类型判断节点」：<br>`是否使用推理模型？`<br>├─ 是 → 跳过手动 CoT，调 reasoning.effort 参数<br>└─ 否 → 保留 DAIR.AI CoT 策略 |
| **是否影响 T-TEXT-001** | ✅ 进阶版 Step 1'/2' 中的 CoT 引导改为条件性 |
| **优先级** | ✅ **P0-3 已完成**（T-CONFIG-003 v0.2 策略判断规范） |

### P0-4：明确 Few-Shot 适用条件

| 项目 | 内容 |
|------|------|
| **问题** | DAIR.AI 将 Few-Shot 作为格式控制的默认手段；但现代模型 Zero-Shot 已足够好，Few-Shot 主要价值是「格式锁定」而非「教模型知识」 |
| **影响范围** | `prompt-kb/01-fundamentals/dair-ai-basic-prompting.md`；<br>`prompt-kb/02-text-prompts/templates/` |
| **建议修改方式** | 在方法论文档中修正默认策略：<br>~~「先用 Few-Shot」~~ → **「先用 Zero-Shot，不满意再加 Few-Shot」**<br>Few-Shot 正确用途标注为「格式锁定 / 边界界定」 |
| **是否影响 T-TEXT-001** | ⚠️ 可能影响，但不修改 T-TEXT-001 核心逻辑，只在方法论说明中更新 |
| **优先级** | ✅ **P0-4 已完成**（T-CONFIG-004 v0.1 Few-shot 适用条件判断规范） |

### P0-5：强化格式示范优于文字描述

| 项目 | 内容 |
|------|------|
| **问题** | 模板中大量用文字描述格式（如"用表格输出"）；OpenAI P4 明确要求用占位符示例展示格式 |
| **影响范围** | `prompt-kb/02-text-prompts/templates/` 下所有含格式说明的模板 |
| **建议修改方式** | 将所有文字格式描述升级为占位符格式示例：<br>~~"用表格，包含品类、销量、环比三列"~~<br>→ `\| 品类 | 销量 | 环比 |\n\| {名称} | {数字} | {百分比} \|` |
| **是否影响 T-TEXT-001** | ✅ 涉及所有模板的格式说明区块 |
| **优先级** | ✅ **P0-5 已完成**（T-CONFIG-005 v0.1 格式描述与占位符规范） |

## 4. 暂缓项 P2

## 6. 推荐执行顺序

### 最小动作 1（P0-2 先做）

**「为所有模板补充分隔符」**

- 改动最小（纯格式调整，不影响逻辑）
- 效果立竿见影（对 OpenAI 标准对齐有最直接提升）
- 作为后续所有修正的基础规范
- **不修改 T-TEXT-001**，从其他简单模板开始试点

### 最小动作 2（P0-5 跟进）

**「将格式说明升级为占位符示例」**

- 在补充分隔符的同时顺便完成
- 改动可见但不影响模型理解
- 与动作 1 合并为「模板格式规范化」单次修改

### 最小动作 3（P0-3 部分先行）

**「在方法论文档中增加模型类型判断」**

- 先修改 `dair-ai-advanced-prompting.md`，不需要改模板
- 为后续 T-TEXT-001 v0.2 打理论基础
- 可以在 T-TEXT-001 正式修改前，先在文档层建立共识

### 最小动作 4（P0-1 独立）

**「在涉及数据查询/报告生成的模板中补充防幻觉段落」**

- 这项改动有明确适用场景，不适合与其他 P0 合并
- 建议选择最常用的 2-3 个模板先试点（如涉及销售分析的模板）
- 其他模板后续泛化

### 最小动作 5（收尾）

**「更新 T-TEXT-001 为 v0.2」**

- 在所有 P0-2、P0-3、P0-5 在其他模板上验证后执行
- 最后一次性完成 T-TEXT-001 的所有小修
- 版本记录中注明「基于 OpenAI 校准 v0.1」

## 7. 阶段结论

**选 A：可以先小修 T-TEXT-001**

但有一个前提条件：**不要等全部 P0 做完再动 T-TEXT-001**。

按以下节奏进行：

```
立即可做（P0-2 + P0-5）：
  → 从非 T-TEXT-001 的简单模板开始试点
  → 积累格式规范修改经验

方法论先行（P0-3）：
  → 先更新 dair-ai-advanced-prompting.md 的模型区分章节
  → 为 T-TEXT-001 v0.2 打理论基础

收尾动作：
  → 汇总试点经验 → 执行 T-TEXT-001 v0.2 修改
```

**不在 Phase 2 做的事（重要）：**

- ❌ 不要全量重构所有模板
- ❌ 不要引入新模型（DeepSeek、Claude）进行横向对比
- ❌ 不要为 OpenClaw 增加多 Agent 框架
- ❌ 不要在 T-TEXT-001 还未稳定时就进行复杂迭代
