## 2. 已完成学习条目

### 2.1 DAIR.AI Introduction（入门）

- **文件**: `01-fundamentals/dair-ai-introduction.md`
- **作用**: 建立 Prompt Engineering 的认知基础——什么是提示词、大模型能做什么/不能做什么、提示词设计的核心原则。
- **产出**: 能力概览表、提示词定义、与大模型的交互模式认知。

### 2.2 DAIR.AI Basic Prompting（基础）

- **文件**: `01-fundamentals/dair-ai-basic-prompting.md`
- **作用**: 掌握两大最基础的提示范式：
  - **Zero-Shot**: 无示例直接提问，适合简单明确的需求
  - **Few-Shot**: 给出 1-N 个示例后让 AI 照做，适合格式/风格/逻辑需要严格对齐的场景
- **产出**: 示例选择策略、高级提示词格式（JSON/YAML/结构化输出）、Zero-Shot vs Few-Shot 决策树。

### 2.3 DAIR.AI Advanced Prompting（高级总览）

- **文件**: `01-fundamentals/dair-ai-advanced-prompting.md`
- **作用**: 7 大进阶技术的系统性总览，建立技术选型能力——面对不同任务能判断该用哪种技术。
- **产出**: 7 大技术卡片索引 + 3 个延期技术摘要 + 技术对比矩阵。

### 2.4 Advanced Techniques 技术卡片（7 张）

独立卡片存放在 `01-fundamentals/advanced-techniques/`：

| 技术 | 文件 | 核心价值 | OpenClaw 适配度 |
|------|------|----------|----------------|
| Chain-of-Thought (CoT) | `cot.md` | 让模型展示推理过程，大幅提升复杂任务准确率 | 单Agent ★★★ / 多Agent ★★★ |
| Self-Consistency | `self-consistency.md` | 多次采样+多数投票，提升推理可靠性 | 单Agent ★★ / 多Agent ★★★★★ |
| Generated Knowledge | `generated-knowledge.md` | 先让模型生成相关知识再推理，弥补领域知识缺口 | 单Agent ★★★★ / 多Agent ★★ |
| Prompt Chaining | `prompt-chaining.md` | 将复杂任务拆分为多步串行Pipeline | 单Agent ★★★★★ / 多Agent ★★★ |
| Tree of Thoughts (ToT) | `tree-of-thoughts.md` | 分支探索多条推理路径，适合决策类问题 | 单Agent ★★★ / 多Agent ★★★★ |
| ReAct | `react.md` | 推理+行动循环，支持工具调用 | 单Agent ★★ / 多Agent ★★★★★ |

**技术基础**：

本模板直接运用了以下 DAIR.AI 方法论：

| 方法论 | 在模板中的体现 |
|--------|---------------|
| **Prompt Chaining** | 三步串行 Pipeline：澄清 → 框架 → 详细生成，步骤间强依赖 |
| **Zero-Shot / Few-Shot** | 标准 7 问版（Few-Shot 思路引导） vs 最小 3 问版（近 Zero-Shot） |
| **结构化输出约束** | Step 1 输出需求文档、Step 2 输出骨架表格、Step 3 固定 5 章节 |
| **温度参数化** | 创意步骤 0.7 / 执行步骤 0.3，区分使用场景 |
| **假设标签体系** | `[待确认]`/`[推断]`/`[默认]` 三级标注，管理信息缺口 |

**四种变体**：

| 变体 | 适用情况 | Token 成本 |
|------|----------|-----------|
| 标准三步版（§6→§7→§8） | 默认推荐，用户愿意配合 | 基准 |
| 最小回答版（§6 子章节） | 低配合度用户，只答 3 题 | ~60% |
| 简化 Zero-Shot 版（§9） | 用户自己心里有数 | ~40% |
| 进阶 CoT+GK 版（§10） | 高价值复杂场景 | 3-4 倍 |

## 5. 当前知识库能力

截至本检查点，Prompt-KB 已具备以下 **6 项核心能力**:

### 5.1 口语化需求转结构化提示词

输入一句模糊的自然语言描述（如"想做个 XX 计划但不知道怎么安排"），能够：
- 自动判断是否属于计划类任务
- 选择合适的模板变体（标准/最小/Zero-Shot/进阶）
- 输出可直接发送给 AI 的完整 prompt

### 5.2 提示策略选型能力

面对不同任务特征，能够判断最优提示策略：

| 任务特征 | 推荐策略 | 知识来源 |
|----------|----------|----------|
| 简单明确 | Zero-Shot | Basic Prompting |
| 格式/风格需对齐 | Few-Shot | Basic Prompting |
| 复杂多步 | Prompt Chaining | Advanced Techniques |
| 需要推理过程 | Chain-of-Thought | Advanced Techniques |
| 需要调用工具 | ReAct | Advanced Techniques |
| 数学/逻辑密集 | CoT 或 PAL | Advanced Techniques |
| 最高准确率要求 | Self-Consistency | Advanced Techniques |
| 模型缺领域知识 | Generated Knowledge | Advanced Techniques |

### 5.3 案例→模板抽象能力

已验证完整的「从单点案例到通用模板」的方法论：
1. 从真实需求出发记录完整案例（CS-001）
2. 识别可参数化的元素并替换为占位符
3. 提炼通用的执行流程（而非具体内容）
4. 设计多种变体适应不同用户类型
5. 用跨领域案例验证抽象完整性

### 5.4 模板迁移性验证能力

建立了系统的模板验证方法：
- 选择与原型场景**差异最大**的领域进行测试
- 按 10 个维度打分（适配判断/Step 1/Step 2/跳步防护/优劣势/改进建议等）
- 给出量化评分和等级判定（A/B/C/D）
- 明确记录是否需要修改模板及优先级

### 5.5 OpenClaw 单 Agent 工作流设计能力

T-TEXT-001 内置 OpenClaw 配置建议：
- **默认方式**: 单 Agent 顺序 Prompt Chaining（步骤间强串行依赖）
- **4 个例外条件**升级为多 Agent: 并行子领域研究 / 多版本生成 / 多利益相关方 / 高频标准化工作流
- 每步的温度参数、输入输出格式均已明确

### 5.6 质量验收与导航管理能力

建立了模板质量门控体系：
- 17 项质量标准（抽象完整度/领域无关性/场景边界/Chaining 理由/各步骤 prompt/变体/Zero-Shot/进阶版/OpenClaw 配置/单多 Agent/失败纠正/非学习示例/即拷即用/长期维护）
- 4 级评分（A≥90/B≥75/C≥60/D<60）
- 导航文件同步更新规范（README/QUICKSTART/模块 README/案例 README）

## 6. 当前不足

### 6.1 方法论层面

| 不足 | 影响 | 严重程度 |
|------|------|----------|
| 尚未经过 **OpenAI 官方提示工程指南** 校准 | 当前仅基于 DAIR.AI 单一来源，可能遗漏 OpenAI 独家最佳实践（如 system prompt 设计、few-shot 示例排序等） | 🟡 中 |
| 缺少 **Anthropic 风格的结构化提示词** 方法 | Anthropic（Claude）的提示工程强调 XML 标签、长上下文分块、角色分离等，与 DAIR.AI 风格互补 | 🟡 中 |
| **APE / Active-Prompt / DSP** 三项延期技术尚未深入学习 | 这三项是自动优化提示词的前沿方向，对未来「AI 自我改进提示词」很重要 | 🟢 低 |

### 6.2 模板层面

| 不足 | 影响 | 严重程度 |
|------|------|----------|
| 模板数量少（仅 1 个已验收） | 只覆盖「计划类任务」单一场景，写作/分析/代码/翻译等其他文本场景尚无模板 | 🟡 中 |
| T-TEXT-001 有 3 条 P2/P3 未修复建议 | 最小回答版维度覆盖、假设比例动态计算、敏感依赖预检 | 🟢 低 |
| 尚无**失败案例**沉淀 | 目前 2 个案例都是成功的，缺少反面教材来验证模板边界 | 🟢 低 |

### 6.3 模块层面

| 不足 | 影响 | 严重程度 |
|------|------|----------|
| **03-image-prompts 图像提示词模块**尚未开始 | 图像生成是日常高频需求，目前完全空白 | 🟠 中高 |
| **04-video-prompts 视频提示词模块**尚未开始 | 视频生成是新兴需求，同样空白 | 🟡 中 |
| **05-openclaw-workflows 多 Agent 协作模块**尚未开始 | T-TEXT-001 仅涉及单 Agent 场景，多 Agent 并行/辩论/层级等模式均未探索 | 🟡 中 |

### 6.4 工程化层面

| 不足 | 影响 | 严重程度 |
|------|------|----------|
| 缺少模板**自动化测试**机制 | 目前靠人工实测验证，无法规模化回归 | 🟢 低 |
| 版本管理依赖手动更新 Markdown header | 无 CI/CD 或脚本自动同步版本号 | 🟢 低 |
| 缺少**效果度量标准**（如用户满意度/任务完成率） | 目前只有内部评分，缺少实际使用反馈数据 | 🟢 低 |

## 7. 下一步建议

按优先级排列的下一步行动：

### P0 — 学习 OpenAI 官方提示工程指南

- **原因**: 用业界另一权威源校准现有 DAIR.AI 方法，补齐 system prompt 设计、对话管理、安全对齐等 DAIR.AI 未充分覆盖的内容
- **预期产出**: OpenAI 最佳实践笔记 + 与现有 DAIR.AI 方法的对照映射表
- **预估工作量**: 1-2 个学习单元
- **前置条件**: 无

### P1 — 学习 Anthropic Prompt Engineering

- **原因**: 补充结构化提示词写法（XML 标签嵌套、长上下文组织、角色指令分离），这对复杂 Agent 工作流至关重要
- **预期产出**: Anthropic 风格提示词指南笔记 + 结构化 prompt 模板骨架
- **预估工作量**: 1-2 个学习单元
- **前置条件**: 建议在 P0 之后，可相互参照

### P2 — 开始图像提示词基础模块

- **原因**: 图像生成是仅次于文本的高频需求，且 维护者有多模态内容生成的实际项目（多 Agent 工作流工具）
- **预期产出**: 03-image-prompts/ 目录初始化 + 至少 1 个图像提示词模板
- **预估工作量**: 2-3 个学习单元
- **前置条件**: 可与 P0/P1 并行

### P3 — 开始视频提示词基础模块

- **原因**: 视频生成是 维护者当前的实际需求（OpenClaw 项目视频）
- **预期产出**: 04-video-prompts/ 目录初始化 + 至少 1 个视频提示词模板
- **预估工作量**: 2-3 个学习单元
- **前置条件**: 建议 P2 之后（图像是视频的基础）

### P4 — 扩展 OpenClaw 多 Agent 协作模板

- **原因**: T-TEXT-001 已验证单 Agent 模式，下一步自然是探索并行研究、多版本对比、辩论式决策等多 Agent 模式
- **预期产出**: 05-openclaw-workflows/ 至少 2 个多 Agent 工作流模板
- **预估工作量**: 3-4 个学习单元
- **前置条件**: 建议 P0+P1 完成后（需要扎实的基础提示词能力作为支撑）

### PX（持续）— 积累更多 T-TEXT-001 实测案例

- **原因**: 1 个迁移案例不足以断言模板普适性，建议每遇到合适的计划类需求都用 T-TEXT-001 跑一遍并记录
- **目标**: 积累到 5+ 个跨领域案例后，统一决定是否采纳 CS-002 提出的 3 条优化建议
- **形式**: 不需要每次都写正式案例文件，简短测试记录即可
