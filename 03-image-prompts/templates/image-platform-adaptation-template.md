## 1. 模板目标

本模板解决以下问题：

| # | 问题 | 说明 |
|---|------|------|
| 1 | 同一个图像需求需要在多个平台测试 | 一份通用提示词无法在 ChatGPT Images、Midjourney、Stable Diffusion 上都生效 |
| 2 | 不同平台的提示词写法差异大 | 有的用自然语言，有的用标签式，有的用参数化写法 |
| 3 | 平台参数容易被误用 | 把 Midjourney 参数直接套到 Stable Diffusion，或把 Stable Diffusion 的 Negative Prompt 格式套到所有平台 |
| 4 | 平台切换时丢失核心信息 | 改写过程中只改语言，丢了主体/场景/风格/光线/色彩/构图 |
| 5 | 不知道什么时候用自然语言，什么时候用参数 | ChatGPT Images 用自然语言，Midjourney 用自然语言+参数，Stable Diffusion 用碎片化标签 |

**核心定位**：T-IMG-002 不是独立的图像提示词规范，而是 T-IMG-001 的平台适配层。它保留 T-IMG-001 定义的 15 维度核心结构，根据不同平台特点调整表达方式。

## 2. 适用范围

### 2.1 适用

| # | 场景 | 说明 |
|---|------|------|
| 1 | 已有通用图像提示词，需要改写到不同平台 | 从一份通用提示词出发，生成 ChatGPT Images / 豆包 / Midjourney / SD / Flux / HF 版本 |
| 2 | 同一个图像需求需要在多个平台测试 | 横向对比不同平台的生成效果 |
| 3 | 需要比较不同平台对同一需求的还原度 | 保持画面核心信息一致，仅调整平台表达方式 |
| 4 | 需要为平台生成中文 / 英文提示词 | 中文 → 豆包 / ChatGPT Images；英文 → Midjourney / SD / Flux |
| 5 | 需要生成平台适配的负面提示词 | 不同平台对负面提示词的支持方式不同 |
| 6 | 需要为图像案例生成平台适配版本 | 如 CS-IMG-001 的案例可经本模板生成各平台版本 |

### 2.2 不适用

| # | 场景 | 原因 |
|---|------|------|
| 1 | 视频生成 | 视频需要时间维度和镜头运动，由后续 T-VIDEO 系列覆盖 |
| 2 | 精确工程制图 | CAD、建筑蓝图等有独立标准，不在 AI 图像生成范围内 |
| 3 | 需要真实人物身份还原的任务 | 涉及隐私和伦理风险 |
| 4 | 高风险或侵权图像生成 | 涉及商标、版权、敏感内容 |
| 5 | 平台参数实时查询 | 平台参数会随版本变化，本模板仅提供通用适配原则，不写死具体参数值 |

## 4. 标准输入区

```markdown
### 原始图像需求

[填写口语化图像需求，例如："我想生成一张知识库封面图，科技感，干净，横版"]

### 通用图像提示词

[填写已经生成的通用中文或英文图像提示词。如果没有，写"无"]

### 使用场景

[封面 / 海报 / 产品图 / 社交媒体配图 / 头像 / 角色图 / 概念图 / 其他]

### 目标平台

[ChatGPT Images / 豆包 / Midjourney / Stable Diffusion / Flux / Hugging Face / 多平台]

### 参考资料

[参考图说明 / 品牌色 / 风格参考 / 人物设定 / 场景设定。如果没有，写"无"]

### 限制条件

[不要出现什么 / 是否避开文字 / 是否避开真实人物 / 是否避开 logo / 品牌标识 / 其他限制]

### 输出要求

[中文提示词 / 英文提示词 / 负面提示词 / 平台适配版本 / 参数建议 / 多版本变体]
```

**使用说明**：
- "原始图像需求"是用户的原话，不要改写；
- "通用图像提示词"是已经生成的中文或英文版本，如果没有就写"无"——本模板可以从通用提示词出发改写，也可以从原始需求直接生成；
- 如果通用提示词为空，本模板会直接从原始需求生成平台版本，相当于执行一次完整的"需求 → 各平台提示词"流程。

## 5. 平台适配总原则

在改写为各平台版本之前，必须先确认以下原则：

| # | 原则 | 说明 |
|---|------|------|
| 1 | 先保留画面核心信息，再做平台改写 | 主体、场景、风格、构图、光线、色彩、细节不能丢 |
| 2 | 不同平台不要强行使用同一种格式 | ChatGPT Images 用自然语言，Stable Diffusion 用标签式，不要混用 |
| 3 | 负面提示词要根据平台支持方式调整 | 有的平台支持独立 Negative Prompt 字段，有的用自然语言表达，有的用 `--no` 参数，有的不支持 |
| 4 | 参数只作为建议，不写死版本 | 如涉及参数示例，必须注明"以当前平台文档为准" |
| 5 | 高风险内容必须保留限制条件 | 无文字、无水印、无 logo、无真实人物等限制不能因为平台切换而丢失 |
| 6 | 有参考图时必须说明参考图用途 | 参考风格？参考构图？参考色彩？参考角色？不能只写"参考附件图" |
| 7 | 平台不支持的参数应改写成自然语言 | 如 ChatGPT Images 不支持 `--ar` 参数，应写成"横版 16:9" |
| 8 | 英文提示词不得丢失中文需求中的限制 | 翻译环节常见遗漏：中文写了"不要人物"，英文只写"modern style"，丢掉了约束 |

## 6. ChatGPT Images 适配规则

### 6.1 平台特点

ChatGPT Images 更适合自然语言描述、图像编辑、风格说明和迭代修改。它理解完整的自然语言句段，不需要碎片化标签或参数化写法。

### 6.2 适配重点

| 要点 | 说明 |
|------|------|
| **语言** | 中文或英文自然语言均可，中文效果良好 |
| **结构** | 使用完整句段描述画面，保持逻辑流畅 |
| **限制条件** | 用自然语言表达限制，如"不包含文字""无 logo""背景干净" |
| **参数** | 不需要复杂参数；画面比例通过对话指定（如"横版 16:9"） |
| **负面提示词** | ChatGPT Images 不支持独立 Negative Prompt 字段——必须将限制条件直接写进正向提示词中 |
| **迭代** | 支持多轮对话修改；可以"保留构图，把背景改成暖色" |
| **改图** | 如果是修改已有图像，需要明确"保留什么、修改什么" |

### 6.3 输出结构

```
### ChatGPT Images 提示词

[自然语言描述的完整中文或英文提示词，包含主体/场景/风格/构图/光线/色彩/限制条件]

### 修改 / 迭代说明

[如果需要多轮修改，给出迭代建议。如："首先生成基础版本，如果不满意色彩，可以追加'把背景调暖一些'"]
[如果不需要迭代，写"可一次性生成"]

### 注意事项

- ChatGPT Images 不支持独立负面提示词字段，所有限制已写入正向提示词；
- 如果结果不满意，可通过多轮对话逐步调整；
- 不适用 `--ar`、`--no`、`--style` 等参数。
```

## 7. 豆包适配规则

### 7.1 平台特点

豆包更适合中文自然语言、社交媒体风格、内容创作场景和短视频生态相关视觉。对中文理解较好，对国风/东方美学风格支持较强。

### 7.2 适配重点

| 要点 | 说明 |
|------|------|
| **语言** | 中文优先，自然语言表达 |
| **结构** | 简洁中文描述，明确使用场景（封面/海报/小红书配图/短视频封面） |
| **风格** | 不要过度参数化，用自然语言描述风格即可 |
| **限制条件** | 可单独给出负面限制，也可以直接写进提示词 |
| **参数** | 平台界面通常可设置图片尺寸；建议在提示词末尾说明比例或尺寸期望 |
| **特点利用** | 如果需求涉及东方美学、国风、中文文化场景，豆包可能有优势 |

### 7.3 输出结构

```
### 豆包中文提示词

[简洁中文自然语言提示词，包含主体/场景/风格/构图/光线/色彩]

### 负面限制

[不出现的内容：文字/水印/logo/真实人物/其他。可填入平台负面提示词字段，或作为独立说明]

### 使用建议

- 中文表达自然，风格描述不要太参数化；
- 可在平台界面设置图片尺寸；
- 适合社交媒体配图、短视频封面、中文内容场景。
```

## 8. Midjourney 适配规则

### 8.1 平台特点

Midjourney 更适合风格化、艺术感、构图、光影和画面审美控制。对英文提示词响应更稳定，支持丰富的参数化控制。

### 8.2 适配重点

| 要点 | 说明 |
|------|------|
| **语言** | 英文提示词通常更稳定 |
| **结构** | 主体和风格靠前，再补充场景、构图、光线、色彩 |
| **参数** | 可加入画面比例（`--ar`）、风格参数（`--style`）等通用参数建议 |
| **版本** | 不写死具体 `--v` 版本号；如示例中出现版本参数，必须标注"版本号仅为示例，以当前平台文档为准" |
| **负面提示词** | 通过 `--no` 参数传入，如：`--no text, watermark, logo` |
| **风格控制** | 可通过 `--style raw` 降低平台自动美化干扰（如有需要） |

### 8.3 输出结构

```
### Midjourney 英文提示词

[英文自然语言 + 参数，主体和风格靠前]

### 参数建议

- `--ar [比例]`：画面比例，如 `--ar 16:9`
- `--no [内容]`：负面排除，如 `--no text, watermark, logo`
- `--style raw`（可选）：降低平台自动美化干扰

> 以上参数为通用建议，版本号（如 `--v 6` 等）以当前平台官方文档为准。

### 注意事项

- Midjourney 对英文响应更稳定，建议使用英文提示词；
- 主体和风格词靠前放置；
- `--no` 参数可排除不需要的内容；
- 具体 `--v` 版本号以当前平台文档为准。
```

## 9. Stable Diffusion 适配规则

### 9.1 平台特点

Stable Diffusion 更适合正向提示词、负面提示词、模型风格、LoRA、ControlNet 等细粒度控制。具体能力取决于用户使用的模型（SD1.5 / SDXL / SD3 等）、界面（ComfyUI / A1111 / Forge 等）和加载的扩展。

### 9.2 适配重点

| 要点 | 说明 |
|------|------|
| **语言** | 英文标签式提示词更常见；部分 SDXL 和 SD3 模型对自然语言支持有所改善 |
| **正向提示词** | 可用碎片化标签：`masterpiece, best quality, [主体描述], [场景], [风格], [光线], [色彩]` |
| **负面提示词** | 独立 Negative Prompt 字段，可更详细：`lowres, bad anatomy, text, watermark, blur...` |
| **模型** | 不假设用户一定使用某个模型；如需模型建议，只给"推荐类型"不写死具体模型名 |
| **参数** | 不写死采样器（sampler）、步数（steps）、CFG Scale 等具体数值；如需要，只给"建议字段" |
| **扩展** | 如果任务涉及 ControlNet / LoRA / IP-Adapter 等，说明用途但不写死具体文件 |

### 9.3 输出结构

```
### Positive Prompt

[英文标签式正向提示词，或自然语言描述（取决于目标模型）]
[结构：质量标签 → 主体 → 场景 → 风格 → 构图 → 光线 → 色彩 → 细节]

### Negative Prompt

[英文负面提示词，独立列出]
[覆盖：低质量/畸形/水印/文字/不需要的内容/不想要的风格]

### Optional Settings

| 字段 | 建议 | 说明 |
|------|------|------|
| 分辨率 | [建议数值，如 1920×1080] | 根据画面比例调整 |
| 采样器 | — | 以当前使用的模型和界面推荐为准 |
| Steps | — | 以当前使用的模型推荐为准 |
| CFG Scale | — | 以当前使用的模型推荐为准 |
| 模型类型建议 | [写实/插画/动漫等] | 不写死具体模型文件名 |

### 注意事项

- 正向和负面提示词格式取决于使用的具体模型（部分模型对自然语言更友好）；
- Optional Settings 中的采样器/Steps/CFG 等不写死数值，以当前模型推荐为准；
- 如果使用 ControlNet / LoRA / IP-Adapter 等扩展，需另外说明用途和配置。
```

## 10. Flux 适配规则

### 10.1 平台特点

Flux 更适合高质量自然语言图像生成，通常可以使用清晰、完整的英文或中文描述。相比传统 Stable Diffusion，Flux 对自然语言的理解更好，细节丰富度高。具体能力取决于部署方式和模型版本。

### 10.2 适配重点

| 要点 | 说明 |
|------|------|
| **语言** | 英文自然语言优先，中文支持有所改善 |
| **结构** | 使用完整自然语言句段，保持主体/场景/风格/构图/光线/色彩完整 |
| **标签式** | 不需要像传统 SD 那样使用碎片化标签，自然语言即可 |
| **负面限制** | 可以用自然语言表达，也可以填入独立字段（取决于具体部署界面） |
| **参数** | 不写死具体模型版本和参数 |

### 10.3 输出结构

```
### Flux 提示词

[英文自然语言完整描述，包含主体/场景/风格/构图/光线/色彩/细节]
[保持句段流畅，不需要碎片化标签]

### 负面限制

[不需要的内容，用自然语言或标签式表达均可]
[示例：no text, no watermark, no logo, no distorted elements]

### 注意事项

- Flux 对自然语言理解较好，不需要传统 SD 的碎片化标签；
- 如果部署界面支持独立 Negative Prompt 字段，可填入"负面限制"；
- 具体模型版本以当前部署环境为准。
```

## 11. Hugging Face 图像模型适配规则

### 11.1 平台特点

Hugging Face 是一个模型集合平台，不是单一图像生成器。上面托管了大量社区和官方的图像生成模型，不同模型的提示词格式、支持的语言、参数接口差异很大。

### 11.2 适配重点

| 要点 | 说明 |
|------|------|
| **先确认模型** | 使用前必须查看模型的 README / Model Card，确认支持的提示词格式 |
| **语言不确定** | SDXL 类模型通常英文；部分社区模型支持中文；以模型说明为准 |
| **格式不确定** | 有些模型偏自然语言，有些偏标签式；不确定时使用简洁自然语言 |
| **负面提示词** | 以模型说明为准——有的支持独立 Negative Prompt，有的不支持，有的通过参数传入 |
| **参数** | 不写死任何模型参数 |
| **通用建议** | 如果不确定，使用简洁英文自然语言 + 负面提示词融入正向描述 |

### 11.3 输出结构

```
### Hugging Face 通用提示词

[简洁英文自然语言描述]
[如模型支持标签式，可额外给出标签版本]
[不确定时，使用自然语言并说明此为通用版本]

### 需要确认的模型信息

| 项目 | 说明 |
|------|------|
| 模型类型 | [SDXL / SD3 / Flux / Kolors / 其他——查看模型 Model Card] |
| 提示词语言 | [英文 / 中文 / 双语——查看模型说明] |
| 提示词格式 | [自然语言 / 标签式 / 混合——查看模型文档和社区示例] |
| 负面提示词支持 | [支持独立 Negative Prompt / 支持参数传入 / 不支持——查看模型说明] |
| 推荐分辨率 | [查看模型文档的建议分辨率] |

### 注意事项

- 以上提示词为通用版本，实际使用时请以具体模型的 README 和文档为准；
- 如果模型不支持负面提示词，应将限制条件写进正向提示词；
- Hugging Face 上模型众多，提示词格式不统一，建议先查看模型的示例 prompt 再调整。
```

## 12. 多平台输出模板

### 12.1 用途

把一个通用图像需求同时改写成多个平台版本。

### 12.2 可复制模板

```markdown
## 多平台适配输出

### 通用需求解析

- **主体**: [从原始需求中提取]
- **场景**: [从原始需求中提取]
- **风格**: [从原始需求中提取]
- **构图**: [从原始需求中提取]
- **光线**: [从原始需求中提取]
- **色彩**: [从原始需求中提取]
- **细节**: [从原始需求中提取]
- **画面比例**: [从原始需求中提取]
- **限制条件**: [从原始需求中提取]

---

### 通用中文提示词
```

## 13. 平台适配检查清单

对每个平台版本逐一检查：

| # | 检查项 | 通过 | 说明 |
|---|--------|------|------|
| 1 | 是否保留主体 | [ ] | 主体的外观、状态、动作是否与原始需求一致 |
| 2 | 是否保留场景 | [ ] | 场景环境、时间是否与原始需求一致 |
| 3 | 是否保留风格 | [ ] | 风格词是否准确，未丢失风格方向 |
| 4 | 是否保留构图 | [ ] | 构图方式（三分法/居中/留白等）是否传递 |
| 5 | 是否保留光线 | [ ] | 光线方向和类型是否传递 |
| 6 | 是否保留色彩 | [ ] | 色彩方案是否传递 |
| 7 | 是否保留负面限制 | [ ] | 限制条件是否根据平台支持方式正确传递 |
| 8 | 是否避免写死平台版本 | [ ] | 未出现具体 `--v X` 等版本号（或已标注"以平台文档为准"） |
| 9 | 是否避免跨平台误用参数 | [ ] | 未将 Midjourney 参数写入 ChatGPT Images 版本；未将 SD 标签式写法写入 Flux 版本 |
| 10 | 是否说明参考图用途 | [ ] | 如有参考图，已说明参考的是风格/构图/色彩还是角色 |
| 11 | 是否保留风险限制 | [ ] | 无文字/无 logo/无真实人物等限制在所有平台版本中均保留 |
| 12 | 是否给出平台差异说明 | [ ] | 多平台输出时已说明各平台提示词的关键差异 |

## 14. 常见错误

| # | 错误 | 说明 | 修正 |
|---|------|------|------|
| 1 | 把 Midjourney 参数直接用于 ChatGPT Images | 在 ChatGPT Images 版本的提示词中写 `--ar 16:9` 或 `--no text` | ChatGPT Images 不支持参数，应写"横版 16:9""不包含文字" |
| 2 | 把 Stable Diffusion Negative Prompt 直接用于所有平台 | 把 `lowres, bad anatomy, text, watermark` 标签式负面词直接放到不支持独立 Negative Prompt 的平台 | 按平台支持方式调整：ChatGPT Images 融入正向；Midjourney 用 `--no` |
| 3 | 英文提示词丢失中文需求里的限制 | 中文写了"不要人物""避开 logo"，英文只写 `modern style, clean background` | 逐条对照原始需求检查英文版本是否覆盖所有限制 |
| 4 | 平台版本号写死 | `--v 6.0`、`--v 7` 等硬编码 | 如必须给出示例，标注"版本号仅为示例，以当前平台文档为准" |
| 5 | 只改语言，不改平台结构 | 中文提示词直接翻译成英文就当作 Midjourney 版本 | 不同平台需要不同的结构和格式，不只是翻译语言 |
| 6 | 忽略目标使用场景 | 封面图写成了方构图，头像写成了横版 | 根据使用场景确定画面比例，再根据平台能力调整表达 |
| 7 | 忽略参考图用途 | "参考附件图片"——没说参考什么 | 明确说明是参考风格、构图、色彩还是角色 |
| 8 | 忽略真实人物 / 商标 / 侵权风险 | 原始需求写了"不要 logo"，适配后漏掉了 | 每次平台改写后，重新检查所有限制条件是否完整 |
| 9 | 给 Hugging Face 写成单一平台 | 对 Hugging Face 像对其他平台一样给出固定格式 | HF 是模型集合，应给出通用版本 + "需要确认的模型信息" |
| 10 | 对简单任务过度参数化 | 一个简单头像需要写 `--ar 1:1 --style raw --v 6 --no...` | 简单任务用简洁版本，只在需要时加参数 |

## 15. 与现有文件关系

### 15.1 与 T-IMG-001 的关系

T-IMG-001 定义图像提示词的 15 维度标准结构（主体、场景、风格、构图、光线、色彩、细节、氛围、画面比例、质量要求、负面提示词、参考图、平台适配说明等），是图像提示词模块的底层规范。T-IMG-002 基于这 15 维度，根据不同平台特点调整表达方式。**T-IMG-002 不重复定义 15 维度的规则，只关注"如何改写到具体平台"。**

### 15.2 与 image-prompt-quick-reference 的关系

quick-reference 是 T-IMG-001 的日常速查卡，提供 15 维度速查表、可复制模板和验收清单。T-IMG-002 是对 quick-reference 中"平台适配说明"维度的展开——quick-reference 第 15 维提醒"跨平台时写目标平台 + 参数建议，不写死版本号"，T-IMG-002 把这一条展开为完整的 6 平台适配模板。

### 15.3 与 CS-IMG-001 的关系

CS-IMG-001 是首个图像提示词实战案例，其 §9 给出了 5 平台的通用适配建议。T-IMG-002 将 CS-IMG-001 §9 的"建议表"扩展为完整的可复制模板，供后续所有图像任务复用。

### 15.4 与 T-CONFIG-003 策略判断的关系

T-CONFIG-003 §11.6 和 §12 定义了图像生成模型的策略判断规则（L1-L5 复杂度、何时用 CoT、何时用 Few-shot 等）。T-IMG-002 的适配决策受 T-CONFIG-003 指导——例如简单封面图（L3）vs 复杂多角色场景图（L5）的平台适配策略不同。

### 15.5 与 T-CONFIG-005 格式和占位符的关系

T-CONFIG-005 §12 定义了图像提示词的格式描述规范，T-CONFIG-005 §15.4 定义了图像任务占位符格式。T-IMG-002 的输出结构（各平台提示词区块）遵循 T-CONFIG-005 的格式规范。

### 15.6 与 T-CONFIG-006 长上下文和参考资料的关系

T-CONFIG-006 §17 定义了图像/视频参考资料的处理规范（参考图的用途说明、来源标注等）。T-IMG-002 的"参考资料"输入区和"参考图用途说明"检查项遵循 T-CONFIG-006 的规定。
