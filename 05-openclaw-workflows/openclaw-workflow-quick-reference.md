## 1. 用途

### ✅ 本速查卡适用于

- 快速判断一个任务该怎么交给 OpenClaw；
- 判断任务类型（创建规范/模板/案例/验收/小修/登记/测试/阶段验收…）；
- 判断任务复杂度（L1-L5）；
- 判断单 Agent / 多 Agent；
- 选择执行流程（创建/验收/小修/登记/测试/阶段验收）；
- 写出可复制的任务指令；
- 检查执行结果是否合格；
- 决定下一步是小修、登记、测试还是阶段验收。

### ❌ 本速查卡不适用于

- 替代 T-OPENCLAW-001 完整规范（详细规则、完整示例请查看完整规范）；
- 直接替代文本 / 图像 / 视频提示词模板；
- 处理违法、高风险或越权任务；
- 代替人工最终判断；
- 定义新的 Agent 平台能力。

## 2. OpenClaw 工作流核心公式

```
OpenClaw 工作流 = 任务识别 + 范围界定 + 资料定位 + 单/多Agent判断
                + 执行计划 + 产物生成 + 验收检查 + 小修处理
                + 导航登记 + 下一步决策
```

> 如果没有"验收检查"和"导航登记"，复杂知识库任务容易变成一次性输出，无法沉淀为可维护资产。

## 3. 18 维度速查表

| # | 维度 | 什么时候必填 | 怎么写 | 常见错误 |
|---|------|-------------|--------|----------|
| 1 | **任务目标** | 每次必填 | 一句话说明目标 | 目标太模糊或太宽泛 |
| 2 | **任务类型** | 每次必填 | 从§4任务类型表中选择 | 不分类直接执行 |
| 3 | **输入资料** | 有资料时必填 | 列出文件路径或内容摘要 | 遗漏关键资料或路径错误 |
| 4 | **参考文件** | 每次必填 | 列出文件路径+用途说明 | 参考过多导致上下文溢出 |
| 5 | **目标文件** | 每次必填 | 列出完整路径 | 路径错误或目标不明确 |
| 6 | **产物类型** | 每次必填 | 规范/模板/速查卡/案例/测试记录/报告 | 类型不清导致结构错误 |
| 7 | **复杂度等级** | 每次必填 | 从§5复杂度表中判断 | 低估复杂度导致遗漏步骤 |
| 8 | **单/多 Agent 判断** | 每次必填 | 参考§6判断规范 | 简单任务用多 Agent 或反之 |
| 9 | **执行顺序** | L2+ 必填 | 列出有序步骤 | 步骤遗漏或顺序颠倒 |
| 10 | **验收标准** | L2+ 必填 | 列出检查项或评分标准 | 无验收标准导致"创建即完成" |
| 11 | **保护文件** | 每次必填 | 显式列出保护清单 | 未列出保护文件导致误改 |
| 12 | **是否需要小修** | 验收后判断 | 根据验收结论判断 | 需要小修时跳过 |
| 13 | **是否需要导航登记** | 创建新文件时 | 创建/验收后必须登记 | 创建了文件但不登记 |
| 14 | **是否需要案例验证** | 新模板/新规范时 | 参考 TEST 经验 | 新模板不验证就投入使用 |
| 15 | **是否需要平台适配** | 图像/视频模板时 | 参考 T-IMG-002/T-VIDEO-002 | 文本任务不需要平台适配 |
| 16 | **是否需要人工确认** | 高风险/不确定时 | 列出需要确认的问题 | 全自动执行高风险任务 |
| 17 | **输出报告** | 每次必填 | 参考§16报告模板 | 不输出报告或报告不完整 |
| 18 | **下一步建议** | 每次必填 | 从候选建议中选择 | 不给下一步建议导致停滞 |

## 5. 复杂度速查

| 等级 | 任务特征 | 推荐方式 | 是否需要拆分 | 是否需要验收 | 是否需要人工确认 |
|------|----------|----------|-------------|-------------|-----------------|
| **L1** | 简单单文件修改（错别字、格式、一行改动） | 单 Agent 直接执行 | 否 | 轻量复核 | 否 |
| **L2** | 单文件创建或小修（新案例、速查卡小修） | 单 Agent 执行 | 否 | 轻量验收 | 否 |
| **L3** | 多文件导航更新 / 案例创建 / 测试记录 | 单 Agent + 清单驱动 | 建议拆分 | 完整验收 | 视情况 |
| **L4** | 新模块基础规范 / 平台适配模板 / 阶段性验收 | 单 Agent 分阶段执行 | 必须拆分 | 完整验收 | 建议确认 |
| **L5** | 跨模块重构 / 多 Agent 协作 / 长链路知识库建设 | 多 Agent 或多轮人工确认 | 必须拆分 | 多轮验收 | 必须确认 |

**使用建议**：
- L1-L2 通常单 Agent
- L3 可单 Agent，但必须有检查清单
- L4 建议分阶段执行
- L5 建议多 Agent 或多轮人工确认

```
任务来了：
  ├─ 只改一个文件的一小部分？ → L1
  ├─ 创建或修改单个完整文件？ → L2
  ├─ 涉及 2-5 个文件？       → L3
  ├─ 创建新模块/新规范？      → L4
  └─ 跨多个模块/需要并行？    → L5
```

## 6. 单 Agent / 多 Agent 判断速查

| 判断问题 | 偏单 Agent | 偏多 Agent | 说明 |
|----------|-----------|-----------|------|
| 目标是否明确？ | ✅ 明确 | ❌ 模糊或需要探索 | 模糊任务先用单 Agent 澄清 |
| 文件范围是否明确？ | ✅ 1-3 个文件 | ❌ 5+ 个文件 | 大范围文件操作可考虑并行 |
| 是否涉及多个模块？ | ❌ 单一领域 | ✅ 文本+图像+视频混合 | 跨领域需要不同专业视角 |
| 是否需要独立评审？ | ❌ 自检即可 | ✅ 需要独立审查 | 高价值产物建议独立评审 |
| 是否需要并行处理？ | ❌ 串行即可 | ✅ 有独立并行分支 | 并行任务适合多 Agent |
| 是否需要风险检查？ | ❌ 风险低 | ✅ 高风险/高价值 | 高风险任务建议独立 Risk Agent |
| 是否需要长上下文？ | ✅ 上下文可控 | ❌ 超长上下文需分块 | 长上下文可拆分处理 |
| 是否涉及高价值结果？ | ❌ 一般任务 | ✅ 重要产物 | 高价值产物建议多轮检查 |
| 是否需要多轮人工确认？ | ❌ 不需要 | ✅ 需要 | 复杂决策需要多轮确认 |

> **简单任务不要过度多 Agent 化**；多 Agent 的价值是职责分离，不是形式主义。

## 7. 多 Agent 角色速查

| Agent 角色 | 负责什么 | 适合什么任务 | 不适合什么情况 |
|-----------|----------|-------------|---------------|
| **Planner Agent** | 任务拆解与执行计划 | L4+ 复杂任务 | 简单单文件任务 |
| **Builder Agent** | 创建规范/模板/案例 | 所有创建类任务 | 验收类任务（不应自己验收自己） |
| **Reviewer Agent** | 质量验收 | L2+ 验收类任务 | 创建类任务（不应代替 Builder） |
| **Refiner Agent** | 小修与版本升级 | 小修类任务 | 大范围重写 |
| **Librarian Agent** | 导航登记与索引维护 | 登记类任务 | 正文创建或修改 |
| **Tester Agent** | 案例测试和平台适配测试 | 测试记录类任务 | 直接修改模板 |
| **Risk Agent** | 风险、边界和保护文件检查 | 高风险任务 | 低风险简单任务 |
| **Summarizer Agent** | 阶段性总结和下一步建议 | 阶段性验收 | 日常简单任务 |

**推荐角色组合**：

| 任务类型 | 推荐组合 |
|----------|---------|
| L1 简单修改 | Builder |
| L2 单文件创建 | Builder + Librarian |
| L3 多文件导航 | Builder + Librarian |
| L4 新规范创建 | Planner + Builder + Reviewer + Librarian |
| L5 跨模块重构 | 全角色 |

## 8. 标准流程：创建类任务

```
1. 明确任务目标
2. 明确参考文件
3. 明确目标文件
4. 限定不修改哪些文件
5. 生成完整 Markdown 文件
6. 输出完成报告
7. 进行质量验收
8. 如需小修则升级版本
9. 通过后登记导航
10. 给出下一步建议
```

**可复制指令骨架**：

```markdown
请创建 [产物名称]。

目标文件：
[文件路径]

参考文件：
[参考文件列表]

创建要求：
[结构 / 章节 / 内容要求]

保护要求：
[不要修改哪些文件]

输出要求：
[完成后需要汇报什么]
```

## 9. 标准流程：验收类任务

```
1. 只读目标文件
2. 检查路径和版本
3. 检查章节完整性
4. 检查核心内容
5. 检查与关联规范的一致性
6. 检查保护文件
7. 输出评分或结论
8. 判断是否需要小修
9. 给出下一步建议
```

**使用建议**：
- 验收任务不要修改文件
- 轻量复核只检查小修点
- 大验收适合新规范 / 新模板
- 案例验收适合检查实际可用性

---

## 10. 标准流程：小修类任务

```
1. 明确修正背景
2. 明确修正位置
3. 限定只修改目标文件
4. 不重写全文
5. 更新版本号
6. 更新版本记录
7. 输出保护文件检查
8. 做轻量复核
9. 通过后登记或进入下一步
```

**可复制指令骨架**：

```markdown
请对 [目标文件] 做一次小修。

修正背景：
[为什么要修]

修正位置：
[章节 / 行 / 小节]

修正内容：
[具体补充或替换内容]

版本要求：
[是否升级版本]

保护要求：
[不要修改哪些文件]

输出要求：
[完成后需要汇报什么]
```

## 11. 标准流程：导航登记类任务

```
1. 确认产物已通过验收
2. 确认路径、编号、版本、状态
3. 更新 README
4. 更新 QUICKSTART
5. 更新模块 README
6. 必要时更新 backlog / 阶段路线
7. 不修改产物正文
8. 输出修改摘要
9. 输出保护文件检查
10. 给出下一步建议
```

> 登记任务只改导航和索引，不应修改正文。

---

## 12. 标准流程：测试记录类任务

```
1. 选择已验收案例作为输入
2. 提取核心信息
3. 按模板生成测试输出
4. 使用检查清单验收
5. 判断是否需要修改模板
6. 写入测试结论
7. 登记测试记录
```

> 测试任务不应修改模板正文；如果发现模板问题，应另开小修任务。

## 13. 标准流程：阶段性验收类任务

```
1. 交付物总览
2. 能力覆盖度
3. 场景覆盖度
4. 闭环检查
5. 当前不足
6. 是否需要继续扩展
7. 是否可以进入下一阶段
8. 阶段性结论
9. 下一步建议
```

> 阶段性验收不应创建新文件或修改导航，除非后续单独执行状态更新任务。

## 14. 保护文件速查

### 常见保护规则

| 场景 | 不应做的事 | 应该做的事 |
|------|-----------|-----------|
| 创建任务 | 顺手修改导航 | 创建完成后单独做导航登记 |
| 验收任务 | 顺手小修问题 | 记录问题，由独立小修任务处理 |
| 小修任务 | 扩大修改范围 | 限定修正位置 |
| 登记任务 | 修改产物正文 | 只更新索引文件 |
| 测试任务 | 修改模板 | 测试记录是独立文件 |
| 阶段验收 | 创建新产物 | 只分析现有产物 |
| 任何任务 | "优化"稳定文件 | 只在有明确理由时修改 |

### 保护文件检查模板

```markdown
请确认：
1. 是否没有修改 [保护文件 1]；
2. 是否没有修改 [保护文件 2]；
3. 是否没有修改 README / QUICKSTART；
4. 是否没有创建额外文件；
5. 是否没有超出本次任务范围。
```

## 15. 失败与返工速查

| 失败类型 | 表现 | 快速修正 | 预防方式 |
|----------|------|----------|----------|
| **会话中断** | 执行到一半断开 | 重新读取文件，从断点继续 | 分阶段执行 |
| **指令不可复制** | 指令太长或格式混乱 | 重新整理，确认关键信息 | 使用结构化指令模板 |
| **输出太长** | 超过上下文限制 | 分段输出，先写核心章节 | 控制单次输出长度 |
| **文件路径错误** | 写入了错误路径 | 检查路径，修正后重新写入 | 写入前先确认目录 |
| **漏改导航** | 创建了文件但没更新索引 | 补充导航登记 | 导航作为独立步骤 |
| **修改范围过大** | 验收时顺手改了正文 | 回退修改，重新限定范围 | 严格遵循保护文件清单 |
| **验收结论不清** | 只说"通过"不说评分 | 补充评分和详细结论 | 使用标准验收报告模板 |
| **搜索循环** | 反复搜索同一内容 | 停止搜索，基于已有信息决策 | 设定搜索次数上限 |
| **重复修改稳定文件** | 反复修改已验收产物 | 回退修改，确认修改理由 | 保护文件清单+范围控制 |
| **没有输出下一步建议** | 执行完就结束 | 补充下一步建议 | 下一步建议作为必要输出 |

## 17. 工作流验收清单

在执行任何 OpenClaw 工作流之前，检查以下项目：

- [ ] 任务目标是否明确？
- [ ] 参考文件是否明确？
- [ ] 目标文件是否明确？
