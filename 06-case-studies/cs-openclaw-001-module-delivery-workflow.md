## 2. 原始任务场景

用户希望让 OpenClaw 完成一个知识库模块产物的完整交付流程。

任务不是只生成一个文件，而是要完成以下链路：

1. 创建一个新模块产物；
2. 对产物做质量验收；
3. 如果发现小问题，进行小修；
4. 小修后做轻量复核；
5. 验收通过后登记导航；
6. 输出完成报告；
7. 给出下一步建议。

该场景来自 Prompt-KB 实际建设过程中的常见任务链路，例如：

- 创建 T-IMG-001 后验收并登记；
- 创建 T-VIDEO-001 后验收并登记；
- 创建 T-VIDEO-002 后验收并登记；
- 创建 T-OPENCLAW-001 后验收并登记。

## 5. 复杂度判断

| 判断项 | 本案例情况 |
|--------|-----------|
| **等级** | L3（多文件导航更新/案例创建） |
| **判断理由** | 创建产物本身是 L2，但加上验收+登记涉及 README/QUICKSTART/模块README/backlog 共 4+ 个文件，整体为 L3 |
| **是否需要拆分** | 建议拆分为：创建→验收→（小修→复核）→登记 |
| **是否需要验收** | ✅ 必须，完整验收 |
| **是否需要人工确认** | 通常不需要，除非产物本身有争议 |
| **是否适合单 Agent** | ✅ 适合，目标明确、范围可控 |
| **是否适合多 Agent** | 可选，但非必要 |

> 如果产物本身是新模块基础规范（如 T-OPENCLAW-001），则整体升级为 L4。

## 6. 单 Agent / 多 Agent 判断

| 判断问题 | 本案例情况 | 倾向 | 说明 |
|----------|-----------|------|------|
| 目标是否明确？ | ✅ 明确（创建+验收+登记） | 单 Agent | — |
| 文件范围是否明确？ | ✅ 明确（目标文件+4 个索引文件） | 单 Agent | — |
| 是否涉及多个模块？ | ❌ 通常在单模块内 | 单 Agent | — |
| 是否需要独立评审？ | ⚠️ 高价值产物建议 | 可选多 Agent | L4 规范建议独立评审 |
| 是否需要并行处理？ | ❌ 串行即可 | 单 Agent | — |
| 是否需要风险检查？ | ❌ 风险低 | 单 Agent | — |
| 是否需要长上下文？ | ⚠️ 参考文件可能较多 | 单 Agent | 可分块处理 |
| 是否涉及高价值结果？ | ⚠️ 新规范/新模板属高价值 | 可选多 Agent | L4 建议确认 |
| 是否需要多轮人工确认？ | ❌ 通常不需要 | 单 Agent | — |

**结论**：推荐 **单 Agent 分阶段执行 + 必要时人工确认**。

## 7. 可选多 Agent 角色分工

即使本案例可以单 Agent 执行，如果采用多 Agent，分工如下：

| Agent 角色 | 在本案例中的职责 | 是否必要 | 说明 |
|-----------|----------------|---------|------|
| **Planner Agent** | 拆解任务为创建→验收→小修→登记步骤 | ❌ 非必要 | L3 任务单 Agent 可自行拆解 |
| **Builder Agent** | 创建目标产物文件 | ✅ 核心 | 必须有人执行创建 |
| **Reviewer Agent** | 质量验收 | ⚠️ 建议 | 独立评审提高质量 |
| **Refiner Agent** | 小修和版本升级 | ⚠️ 视情况 | 验收发现问题时需要 |
| **Librarian Agent** | 导航登记 | ✅ 核心 | 必须有人执行登记 |
| **Tester Agent** | 案例测试和平台适配测试 | ❌ 非必要 | 本案例不涉及测试 |
| **Risk Agent** | 保护文件检查 | ❌ 非必要 | L3 风险低，Builder 自检即可 |
| **Summarizer Agent** | 输出完成报告和下一步建议 | ❌ 非必要 | Builder 可自行输出 |

**推荐组合**：L3 → Builder + Librarian（创建+登记）；L4 → Planner + Builder + Reviewer + Librarian

## 8. 推荐执行流程

| 步骤 | 目标 | 输入 | 输出 | 是否需要人工确认 |
|------|------|------|------|-----------------|
| 1. 创建目标产物 | 生成完整 Markdown 文件 | 任务指令+参考文件 | 目标文件草稿 | 否 |
| 2. 输出完成报告 | 记录创建了什么 | 创建结果 | 完成报告 | 否 |
| 3. 质量验收 | 检查产物质量 | 目标文件+验收标准 | 评分+问题清单+结论 | 否 |
| 4. 小修（如需） | 修正验收发现的问题 | 问题清单+目标文件 | 修正后文件+版本记录 | 否 |
| 5. 轻量复核（如需） | 确认小修正确 | 修正内容 | 通过/不通过 | 否 |
| 6. 导航登记 | 更新索引 | 验收结论+产物信息 | 更新后的 README/索引 | 否 |
| 7. 保护文件检查 | 确认没有误改 | 执行过程 | 保护文件检查清单 | 否 |
| 8. 更新阶段路线 | 更新 Phase 状态 | 登记结果 | 更新后的 backlog | 否 |
| 9. 给出下一步建议 | 指引后续方向 | 当前状态 | 下一步建议 | 否 |

## 13. 保护文件与范围控制

| 场景 | 不得修改 | 原因 | 检查方式 |
|------|---------|------|----------|
| **创建任务** | README/QUICKSTART/模块README/backlog | 创建和登记分离 | 输出保护文件检查 |
| **验收任务** | 目标文件正文 | 验收只读不写 | 确认没有写入操作 |
| **小修任务** | 其他模块文件、已稳定文件 | 限定修正范围 | 列出保护清单 |
| **登记任务** | 产物正文 | 登记只改索引 | 确认没有修改正文 |
| **测试任务** | 模板正文 | 测试记录是独立文件 | 确认没有修改模板 |
| **阶段验收** | 任何文件 | 验收只分析不修改 | 确认没有写入操作 |
| **所有任务** | 超出任务范围的文件 | 防止范围漂移 | 任务开始时列出保护清单 |

## 14. 失败与返工处理

| 失败类型 | 本案例中的表现 | 修正方式 | 预防方式 |
|----------|---------------|----------|----------|
| **指令不可复制** | 用户指令太长或格式混乱 | 重新整理指令，确认关键信息 | 使用结构化指令模板（§9-§12） |
| **输出太长** | 案例文件超过上下文限制 | 分段输出，先写核心章节 | 控制单次输出长度 |
| **会话中断** | 执行到一半断开 | 重新读取文件，从断点继续 | 分阶段执行 |
| **漏改导航** | 创建了文件但没更新索引 | 补充导航登记 | 导航作为独立步骤（§12） |
| **修改范围过大** | 验收时顺手改了正文 | 回退修改，重新限定范围 | 严格遵循保护文件清单 |
| **验收结论不清** | 只说"通过"不说评分 | 补充评分和详细结论 | 使用标准验收报告模板（§10） |
| **反复搜索循环** | 反复搜索同一参考文件 | 停止搜索，基于已有信息决策 | 设定搜索次数上限 |
| **误改稳定文件** | 登记时修改了产物正文 | 回退修改，确认修改理由 | 保护文件清单+范围控制 |
| **忘记下一步建议** | 执行完就结束 | 补充下一步建议 | 下一步建议作为必要输出 |
