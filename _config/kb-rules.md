## 核心原则

### 1. 渐进式积累
- **不贪多**: 每次只处理一个资源的一个章节
- **重质量**: 每个条目都要经过验证，不是泛泛总结
- **及时用**: 学到的模板尽快在 OpenClaw 中实践

### 2. 知识转化优先
- 禁止只做摘要或摘录
- 必须转化为**我的**可执行提示词模板
- 必须说明 OpenClaw 如何使用
- 必须标注单 Agent / 多 Agent 适配度

### 3. 安全第一
- 所有外部操作（文件/命令/邮件/日历/外部工具）必须人工确认
- 不确定的操作，宁可多问一句

## 条目创建规则

### 必须包含
- [ ] 标准 15 个字段全部填写
- [ ] 至少 1 个实际示例
- [ ] 明确的单/多 Agent 标注
- [ ] 安全注意事项（如有外部操作）

### 禁止行为
- ❌ 全文搬运资源内容
- ❌ 只做摘要不转模板
- ❌ 不测试就声称可用
- ❌ 跳过安全确认

### 推荐流程
```
资源 → 单章节 → 提炼核心 → 生成模板 → 测试验证 → 复盘改进 → 入库
```

## 资源处理规则

### 每次只处理一个资源的一个章节

**允许**:
- 一次只学 DAIR.AI 的 Introduction
- 一次只学 OpenAI 指南的 "Clear Context"

**不允许**:
- 一次学完整个 DAIR.AI 指南
- 同时处理多个资源

### 转化标准

每个知识库条目必须：
1. 有**中文提示词模板**（可复制使用）
2. 有** OpenClaw 使用说明**
3. 有**单/多 Agent 标注**
4. 有**常见失败和修正提示**

## 外部操作安全规则

### 必须人工确认的操作

| 操作类型 | 关键词 | 确认时机 |
|----------|--------|----------|
| 文件删除 | delete, remove, rm | 执行前 |
| 文件覆盖 | overwrite, write to | 执行前 |
| 命令执行 | bash, powershell, cmd | 执行前 |
| 邮件发送 | send email, 发送邮件 | 执行前 |
| 日历修改 | calendar, 日程, meeting | 执行前 |
| 外部 API | api call, http request | 执行前 |
| 费用产生 | cost,花钱,付费 | 执行前 |

### 确认格式

````markdown
⚠️ **人工确认需要**

即将执行: [操作描述]
影响范围: [具体说明]
请回复 "确认" 后继续，或提供修正意见。
````

## 新模板创建规则

所有新建 Prompt-KB 模板，默认必须参考：

`prompt-kb/_config/prompt-template-style-guide.md`（T-CONFIG-001 v0.2）

除非属于以下例外类型，否则新模板应包含：

| 必要字段 | 说明 |
|----------|------|
| 模板编号 | 如 T-TEXT-00X、T-IMG-00X 等 |
| 适用场景 | 明确说明模板适合的任务类型 |
| 不适用场景 | 明确说明模板不适合的情况 |
| 标准输入区 | 模板的标准输入格式 |
| 参考资料区 | 外部资料引用机制（如适用） |
| 输出格式 | 明确的输出格式要求 |
| 常见失败 | 已知失败模式和应对方法 |
| 修正提示 | 出问题时如何调整 |
| OpenClaw 使用方式 | 单 Agent / 多 Agent / 执行模式建议 |
| 版本记录 | 变更历史（至少初始版本） |

**例外类型**（无需遵守上述结构）：

- 学习笔记
- 案例复盘
- 临时草稿
- 原始资料摘要
- 外部资源索引

## 策略选择规则

所有新建 Prompt-KB 模板，在设计前应先参考：

`prompt-kb/_config/model-strategy-selection-guide.md`（T-CONFIG-003 v0.2）

**基本规则**：
- 不确定任务复杂度时，先判断 L1-L5 等级
- 简单任务不要过度工程化（L1 用 Zero-Shot 即可）
- 模糊任务不要直接生成最终结果，应先澄清需求
- 输出格式不稳定时才考虑 Few-shot
- 多步骤任务优先 Prompt Chaining
- 普通任务默认单 Agent
- 多 Agent 仅在职责明显不同、可并行、需要审查或长期自动化时使用
- 涉及文件、邮箱、日历、命令行、外部工具写入等操作时，必须 human-in-the-loop
- 图像 / 视频任务使用专门模块，不要套用纯文本模板结构

> 完整规范见 T-CONFIG-003，包含决策树、可复制策略判断提示词和常见误判。

## Few-shot 适用条件规则

所有新建 Prompt-KB 模板，在决定是否加入示例前，应参考：

`prompt-kb/_config/few-shot-usage-decision-guide.md`（T-CONFIG-004 v0.1）

**基本规则**：
- 不要为了完整性强行加入 Few-shot
- 任务简单、输入清楚时优先 Zero-Shot
- 输出格式不稳定时考虑 Few-shot
- 需要固定风格或结构时考虑 Few-shot
- 用户不知道怎么填写时，可以加入 1 个示例
- 有信息不足或边界场景时，可以加入 2-3 个示例
- 示例超过 3 个时，优先迁移到案例库
- Prompt Chaining 不需要每一步都加入示例
- 确认需要 Few-shot 后，再参考 T-CONFIG-002 编写示例

> 完整规范见 T-CONFIG-004，包含 16 场景决策总表、Zero-Shot/Few-shot/案例库边界、Prompt Chaining/图像/视频/OpenClaw 判断规则、决策树和可复制判断提示词。

## 格式描述与占位符规则

所有新建 Prompt-KB 模板，在设计输入区、输出格式和占位符时，应参考：

`prompt-kb/_config/format-and-placeholder-guide.md`（T-CONFIG-005 v0.1）

**基本规则**：
- 普通占位符统一使用中文方括号，例如 [主题]、[目标用户]、[参考资料]
- 不确定信息统一标记为 [待确认]
- 合理假设统一标记为 [假设]
- 不使用大括号作为普通占位符，避免和 JSON 冲突
- 不使用尖括号作为普通占位符，避免和 XML 标签混淆
- 用户输入、参考资料和限制条件应尽量分区
- 没有内容时写"无"，不要留空
- 面向中文用户阅读时优先 Markdown
- 机器读取或自动化流程优先 JSON
- OpenClaw 配置和工作流参数优先 YAML
- 表格适合短字段，不适合长段落
- 图像 / 视频任务应使用专门的视觉或时间维度占位符

> 完整规范见 T-CONFIG-005，包含占位符示例库、Markdown/表格/JSON/YAML 输出格式规范、图像/视频提示词格式描述、OpenClaw 工作流格式、常见格式错误和可复制格式判断提示词。

## 长上下文输入规则

所有新建 Prompt-KB 模板，如果涉及长文档、多来源资料或参考资料，应参考：

`prompt-kb/_config/long-context-input-guide.md`（T-CONFIG-006 v0.1）

**基本规则**：
- 用户输入和参考资料必须分开
- 多来源资料必须编号（资料 1、资料 2…）
- 每个来源尽量标注来源名称、来源类型、日期和可信度
- 没有资料时写"无"，不要留空
- 不确定信息统一标记为 [待确认]
- 合理假设统一标记为 [假设]
- 资料中没有的信息不能伪装成事实
- 资料冲突时必须列出冲突点和来源，不要自行选择一个当作绝对事实
- 资料不足时先说明缺口，再给出可选假设
- 长资料应先摘要，再分析
- 资料太长时应分块处理
- OpenClaw 长上下文任务默认优先单 Agent 顺序执行
- 涉及重要决策、资料冲突、高风险内容或外部写入操作时，必须 human-in-the-loop

> 完整规范见 T-CONFIG-006，包含长上下文任务判断表、7 区块标准输入结构、10 种来源类型处理要点、可信度判断表、冲突处理模板、资料不足处理模板、摘要规范、分块规范、引用规范、OpenClaw 工作流（6 步）、多 Agent 判断表和可复制模板。

## Few-shot 示例规则

所有新建 Prompt-KB 模板，如果需要示例，应参考：

`prompt-kb/_config/few-shot-example-guide.md`（T-CONFIG-002 v0.2）

**基本规则**：
- 默认 1 个示例；复杂模板可放 2-3 个示例
- 超过 3 个示例时，优先迁移到案例库（`06-case-studies/`）
- 示例必须区分输入和期望输出
- 示例中的不确定信息统一标记为 `[待确认]`
- 带参考资料的示例必须单独提供「参考资料」区，输出中须有 `[引用来源]` 标注
- 示例不能污染主任务（模型不应照抄示例中的具体内容）
- 示例不能包含真实隐私信息

> 完整规范见 T-CONFIG-002，包含三类标准示例（正常/信息不足/边界）、设计原则和验收清单。
