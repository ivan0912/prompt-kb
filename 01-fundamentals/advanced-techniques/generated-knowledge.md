# Generated Knowledge (GK) — 生成知识增强

> 🟢 **立即掌握** | DAIR.AI Advanced Prompting #3 | [返回总览](../dair-ai-advanced-prompting.md)

---

## 1. 一句话解释

**先让模型生成与问题相关的背景知识，再把知识和问题一起喂给它做最终回答。**

```
❌ 直接问：
   "高尔夫的一部分目标是比其他人得到更高的总分。对吗？"
   → 模型可能答：对。（❌ 错！高尔夫是杆数越低越好）

✅ 先生成知识再回答：

Step 1 — 生成知识：
   "关于高尔夫运动的知识："
   → 模型生成："高尔夫是用最少杆数完成所有球洞的运动。
      一轮 18 洞，每杆计为 1 分，总杆数最低者获胜。"

Step 2 — 结合知识回答：
   "知识：高尔夫的目标是用最少的杆数完成所有球洞...
    问题：高尔夫的一部分目标是比其他人得到更高的总分吗？
    回答：不对。高尔夫的目标是总杆数越少越好。" ✅
```

---

## 2. 适合什么时候用

- ✅ **常识推理易错领域** — 模型经常在常识问题上"自信地瞎编"
- ✅ **你不熟悉的专业领域** — 担心模型也不懂或编造事实时
- ✅ **需要补充背景上下文的问答** — 问题缺少必要的领域知识
- ✅ **新品类/新产品分析** — 需要先了解市场特点再做判断

---

## 3. 不适合什么时候用

- ❌ **你自己很熟悉的领域** — 自己的知识通常比模型生成的更可靠
- ❌ **简单事实查询** — 直接问就行，两阶段反而浪费时间
- ❌ **模型对该领域完全无知** — 生成的知识也可能是错的（垃圾进垃圾出）
- ❌ **Token 预算紧张的场景** — 两阶段调用 roughly 翻倍 token 消耗
- ❌ **需要实时/精确信息的场景** — GK 生成的是"一般知识"，不是实时数据

---

## 4. 关键发现

- **生成的知识质量直接影响最终答案** — 好知识 → 好答案
- **不同知识可能导致不同置信度的答案** — 有些知识更有帮助
- **特别适合 Common Sense Reasoning（常识推理）任务**
- **GK 是"辅助"而非"权威"** — 如果你有领域知识，用自己的做交叉验证

---

## 5. 中文提示词模板

### 模板：Generated Knowledge 两阶段推理 🟡

```markdown
## Phase 1：生成相关知识

关于"{主题}"，请列出 5 条与此问题相关的背景知识或事实。

## Phase 2：基于知识回答

**背景知识：**
{Phase 1 生成的知识}

**问题：** {原始问题}

请结合上述背景知识，逐步分析并给出答案。如果知识与问题矛盾，以知识为准并说明原因。
```

**填空示范——新品类判断：**
```markdown
## Phase 1：生成相关知识

关于"儿童科学实验玩具市场特点"，请列出相关的行业知识和消费规律。

## Phase 2：基于知识回答

**背景知识：** {上面生成的知识}

**问题：** 我们的新品"STEM 物理实验套装"定价 168 元，
首周销量 45 件，这个表现算好还是差？

请结合上述背景知识，逐步分析并给出答案。
```

**增强版——多知识源 + 交叉验证：**
```
Phase 1：生成 5 个不同的知识片段（而非 1 个）
Phase 2：让模型评估哪个知识最可靠（meta-reasoning）
Phase 3：只用最可靠的知识做最终回答
Phase 4：如果多个知识互相矛盾，标记为"不确定性高"
```

## 6. OpenClaw 使用方式

### 配置方案：GK 增强型单 Agent

```
┌───────────────────────────────────────────────────┐
│            GK-Enhanced Agent                       │
├───────────────────────────────────────────────────┤
│ Phase 1 — 知识生成（同一 Agent，第一次调用）：       │
│                                                   │
│   System Prompt:                                  │
│     你是一个知识提取助手。                          │
│                                                   │
│   User Message:                                   │
│     关于"{用户问题的主题}"，                       │
│     请列出 5 条相关背景知识或事实。                │
│                                                   │
│ ← 保存输出为 knowledge 变量                        │
│                                                   │
│ Phase 2 — 结合知识回答（同一 Agent，第二次调用）：   │
│                                                   │
│   User Message:                                   │
│     **背景知识：** {knowledge}                    │
│     **问题：** {用户的原始问题}                   │
│     请结合上述背景知识，逐步分析并给出答案。         │
└───────────────────────────────────────────────────┘
```

**注意：** 也可以用两个独立 Agent（Agent A 生成知识 → Agent B 回答），但单 Agent 两阶段调用更简单。

---

## 7. 单 Agent 适配度

# ★★★★☆ (4/5)

**原因：**
- GK 的两阶段（生成知识 → 结合回答）可以在单 Agent 内部完成
- 实现简单：两次调用，中间变量传递知识文本
- **但要注意：** 如果 Agent 本身就不懂该领域，生成的知识也不可信

---

## 8. 多 Agent 适配度

# ★★★★☆ (4/5)

**原因：**
- 可以拆分为两个 Agent：知识生成 Agent + 回答 Agent
- 也可以在 Prompt Chaining pipeline 中作为其中一个步骤
- 多 Agent 方式的优势：知识生成 Agent 可以专门优化为"知识提取"角色

---

## 9. 常见失败

| # | 失败模式 | 典型表现 | 根本原因 |
|---|----------|----------|----------|
| 1 | **生成错误知识** | 模型生成了错误的知识，导致最终答案更离谱 | GK 质量取决于模型能力——不懂的领域生成的也不可信 |
| 2 | **知识与问题矛盾** | Phase 1 的知识和 Phase 2 的直觉冲突，模型困惑 | 需要在 prompt 中明确"以知识为准"的优先级规则 |
| 3 | **生成知识过于泛泛** | "玩具是给孩子玩的"这种废话知识 | 需要限定知识的具体性和相关性 |
| 4 | **两阶段 Token 翻倍** | 简单问题也走完两阶段，浪费 token | 应先判断是否真的需要 GK |

## 10. 修正提示

### 修正：Generated Knowledge 不可信 → 多知识源 + 交叉验证

**❌ 错误：** 模型生成了一个错误的知识，然后据此给出了错误的自信答案

**✅ 修正——生成多个知识 + 选择最合理的：**
```
Phase 1：生成 5 个不同的知识片段（而非 1 个）
Phase 2：让模型评估哪个知识最可靠（meta-reasoning）
Phase 3：只用最可靠的知识做最终回答
Phase 4：如果多个知识互相矛盾，标记为"不确定性高"

⚠️ 根本原则：Generated Knowledge 是"辅助"而非"权威"。
   如果你对某个领域有一定了解，用自己的知识做交叉验证。
```

**改进 Phase 1 Prompt 以获得更好的知识质量：**
```markdown
关于"{主题}"，请列出 5 条与此问题高度相关的背景知识。
要求：
1. 每条知识必须是具体的事实或规律（不要泛泛而谈）
2. 如果涉及数量/比例/阈值，尽量给出具体数字
3. 如果有不同的观点或例外情况，请注明
4. 标注你对每条知识的置信度（高/中/低）
```

## 11. 示例

### 场景：新品类上市表现评估

**需求：** 新上的 STEM 物理实验套装，首周销量 45 件，定价 168 元。这个表现好不好？我们对这个细分市场不熟悉。

**GK 两阶段应用：**

**Phase 1 输出（模拟）：**
```
关于儿童科学实验玩具市场的相关知识：
1. STEM 玩具属于教育属性强的高客单价品类，均价 98-268 元
2. 新品冷启动期（前 2 周）销量通常较低，属于正常现象
3. 该品类复购周期长（3-6 个月），首周更多是"尝鲜"购买
4. 寒暑假和开学季是旺季，平时销量约为旺季的 40-60%
5. 定价 168 元处于中高端区间，目标客群为重视教育的城市家长
```

**Phase 2 输出（基于以上知识）：**
```
综合分析：定价 168 元处于 STEM 玩适中高端区间（合理定位），首周 45 件
对于高客单价教育玩具的新品来说属于正常范围（参考知识 #2 和 #3）。
但需要注意：如果不是旺季时段，45 件的绝对值需要结合同期同类新品对比。

初步判断：表现正常偏乐观，建议观察 3 周趋势后再做最终评定。
置信度：中（缺乏历史对比数据）
```

## 12. 与其他技术的组合方式

| 组合 | 方式 | 效果 |
|------|------|------|
| **GK + CoT** | 先 GK 补充知识，再用 CoT 逐步推理 | 最常用组合——知识 + 推理双增强 |
| **GK + Self-Consistency** | GK 后用 SC 多票投票 | 对高可靠性需求的领域知识问答 |
| **GK + Prompt Chaining** | Chaining 的 Step 1 用 GK 生成领域知识，后续步骤引用 | 适用于整个 pipeline 都需要领域上下文的场景 |
