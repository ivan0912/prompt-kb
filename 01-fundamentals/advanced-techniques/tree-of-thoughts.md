# Tree of Thoughts (ToT) — 思维树

> 🟡 **了解概念** | DAIR.AI Advanced Prompting #5 | [返回总览](../dair-ai-advanced-prompting.md)

---

## 1. 一句话解释

**不只沿一条线思考，而是同时探索多条思路，评估每条思路的价值，必要时回溯重试。**

```
线性 CoT：     Step 1 → Step 2 → Step 3 → 答案（只有一条路）

Tree of Thoughts:
              Start
              / | \
           思路A 思路B 思路C    ← 同时探索多条路
            / \    |
         A1   A2  B1            ← 继续展开
          ↓    ↓   ↓
        评估! 评估! 评估!        ← 判断哪条路有前途
          ↓
       选最优路径 → 答案          ← 必要时可以回头选别的
```

---

## 2. 适合什么时候用

- ✅ **需要多方案对比选优的策略性问题** — "有几种做法，哪种最好？"
- ✅ **创意写作规划** — 先发散想几个方向，再收敛选最好的
- ✅ **Game of 24（24 点游戏）** — 经典 ToT 验证场景
- ✅ **需要"回溯"能力的规划任务** — 第一条路走不通时要换路线
- ✅ **多 Agent 并行探索** — 每个 Agent 探索一条路径

---

## 3. 不适合什么时候用

- ❌ **日常简单推理** — CoT 就够了，ToT 是杀鸡用牛刀
- ❌ **线性问题（只有唯一解法）** — 不需要分支探索
- ❌ **Token/成本敏感场景** — ToT 需要维护多条候选路径，token 开销大
- ❌ **低延迟要求的实时任务** — 多轮评估增加响应时间
- ❌ **单次调用场景** — ToT 本质上需要多轮交互式搜索

---

## 4. 与 CoT 的本质区别

| | CoT（思维链） | ToT（思维树） |
|--|-------------|-------------|
| 路径数量 | 1 条（线性） | 多条（分支） |
| 能否回溯 | 不能 | 可以 |
| 搜索策略 | 无 | BFS / DFS / Beam Search |
| 计算成本 | 低 | 高（需要多候选 + 评估） |
| 适合问题 | 直线推理 | 需要探索/规划的复杂问题 |

## 5. 中文提示词模板

ToT 不是单一 prompt，而是**多轮交互式搜索过程**。以下是核心 prompt 结构：

### Phase 1：发散——生成候选思路

```markdown
针对以下问题，请提出 {N} 种不同的解决思路或假设。
每种思路需要：
1. 简述核心想法
2. 预期的优点
3. 潜在的风险或局限

问题：{问题描述}
```

### Phase 2：评估——逐条评价

```markdown
以下是针对"{问题}"的几种候选思路：
{候选思路列表}

请逐一评估每种思路：
1. 可行性（1-5 分）
2. 预期效果（1-5 分）
3. 风险等级（低/中/高）
4. 综合推荐排序

最后给出你的最优选择及理由。
```

### Phase 3：展开——深入发展最优路径

```markdown
基于评估结果，我们选择了"{最优思路}"作为主要方向。
请沿着这条思路进一步展开详细的执行计划或推理过程。

{可选：如果此路径遇到死胡同，回溯到第二优选项}
```

## 6. OpenClaw 使用方式

### 配置方案：ToT 多 Agent 并行探索

```
┌─────────────┐
 │   Coordinator │
 │    (协调者)    │
 └──────┬───────┘
    ┌────┼────┬────────┐
    ↓    ↓    ↓        ↓
┌──────┐┌──────┐┌──────┐
│Path A││Path B││Path C│  ← 并行探索多条思路
│Agent ││Agent ││Agent │
└──┬───┘└──┬───┘└──┬───┘
   ↓       ↓       ↓
 评估     评估     评估
   └───────┼───────┘
           ↓
    选最优路径 → 最终答案
```

**实现要点：**
- 协调者 Agent 负责分发任务和汇总结果
- 每个 Path Agent 独立探索一条思路
- 评估可以是协调者做，也可以单独一个 Evaluator Agent
- 支持 BFS（广度优先）或 DFS（深度优先）搜索策略

---

## 7. 单 Agent 适配度

# ★★★☆☆ (3/5)

**原因：**
- ToT 需要多轮交互（发散→评估→展开→回溯），单 Agent 顺序执行效率低
- 单 Agent 做 ToT 本质上是在模拟多路径搜索，不如真正的多 Agent 并行
- **可行但不推荐**——简单 ToT（2-3 个候选）可以用单 Agent 多轮实现

---

## 8. 多 Agent 适配度

# ★★★★★ (5/5)

**原因：**
- **ToT 的分支探索可以用多 Agent 并行实现**——每个 Agent 探索一条路径
- 这是 ToT 的理想架构：并行探索 + 集中评估
- 天然适合分布式/并发执行

---

## 9. 常见失败

| # | 失败模式 | 典型表现 | 根本原因 |
|---|----------|----------|----------|
| 1 | **用于日常简单任务** | 为了回答一个简单问题动用了复杂的树搜索 | ToT 有明确的适用边界，日常任务用 CoT 就够了 |
| 2 | **候选数量过多** | 生成 10 个候选，评估阶段 itself 成为瓶颈 | 2-5 个候选通常足够，太多反而降低质量 |
| 3 | **评估标准模糊** | 每条路径都打了 4 分，无法区分优劣 | 需要具体的量化评估指标 |
| 4 | **无限展开** | 一直在展开子路径，永远不到最终答案 | 需要设置最大深度（max_depth）和终止条件 |
| 5 | **过早收敛** | 第一条看起来不错的路径就被选定，没有充分探索 | 评估阶段要有一定的探索意愿 |

## 10. 修正提示

### 修正：高级技术选型错误 → 用决策树重新判断

```
Q1: 这个任务模型不做推理能好吗？（能 → Basic Prompting）
Q2: 需要推理的话，一句"逐步思考"够吗？（够 → Zero-Shot CoT）
Q3: 需要高精度吗？（是 → 加 Self-Consistency 或 PAL）
Q4: 需要外部信息吗？（是 → ReAct / 工具调用）
Q5: 是复杂多步流程吗？（是 → Prompt Chaining）
Q6: 是否真的需要多方案对比？（是 → ToT；否 → 以上某项就够了）
Q7: 以上都不匹配？→ 可能根本不该用这些高级技术
```

**ToT 专用修正：**
```
- 候选数量控制在 2-5 个
- 评估必须有量化标准（打分 + 具体理由）
- 设置最大搜索深度（建议 2-3 层）
- 如果最优路径明显优于其他，不必强行展开所有路径
```

## 11. 示例

### 场景：促销策略选择

**需求：** "双十一快到了，我们积木套装品类有 3 种促销方案可选，哪个最好？"

**ToT 应用：**

**Phase 1 — 发散（3 条路径）：**
- **路径 A：满 199 减 30** — 传统促销，门槛适中
- **路径 B：买二送一** — 清库存导向，但毛利受损
- **路径 C：会员专享 8 折** — 提升复购，但覆盖面窄

**Phase 2 — 评估：**
| 维度 | 路径 A | 路径 B | 路径 C |
|------|--------|--------|--------|
| 预期销量提升 | +25% | +40% | +15% |
| 毛利影响 | -8% | -22% | -12% |
| 库存压力 | 中 | 低（清库存） | 高 |
| 用户体验 | 好 | 一般 | 会员好/非会员差 |
| 综合得分 | 4.0 | 3.5 | 3.0 |

**Phase 3 — 结论：** 选路径 A，辅以路径 C 作为会员追加优惠。

## 12. 与其他技术的组合方式

| 组合 | 方式 | 效果 |
|------|------|------|
| **ToT + CoT** | ToT 的每条路径内部用 CoT 推理 | 默认组合——路径展开需要详细推理 |
| **ToT + 多 Agent 并行** | 每个 Agent 探索一条 ToT 路径 | ToT 的理想实现方式 |
| **ToT + Prompt Chaining** | ToT 作为 Chaining 中的一个步骤 | 适用于"需要先选方案再执行"的场景 |
