# Program-Aided Language Models (PAL) — 程序辅助语言模型

> 🟡 **了解概念** | DAIR.AI Advanced Prompting #7 | [返回总览](../dair-ai-advanced-prompting.md)

---

## 1. 一句话解释

**让模型把推理过程写成代码（Python），然后交给程序解释器执行得到精确答案。**

```
❌ CoT 用自然语言算日期：
   "2023年2月27日的25年前... 应该是1998年左右..."
   → 可能算错 ✗

✅ PAL 让模型写代码：
   from datetime import datetime
   from dateutil.relativedelta import relativedelta
   today = datetime(2023, 2, 27)
   born = today - relativedelta(years=25)
   born.strftime('%m/%d/%Y')
   → 执行代码 → '02/27/1998' ✅ 精确无误
```

---

## 2. 适合什么时候用

- ✅ **数学计算** — 特别是涉及日期、利率、百分比等容易出错的计算
- ✅ **数据分析** — 需要对数值数据做精确运算（求和/平均/标准差等）
- ✅ **需要精确保真的场景** — 金融报表、科学计算、工程量估算
- ✅ **CoT 反复算错的场景** — 自然语言推理在某些计算任务上不可靠
- ✅ **有代码执行环境** — 可以运行 Python / 其他解释器

---

## 3. 不适合什么时候用

- ❌ **没有代码执行环境** — PAL 的核心就是"写代码→执行"，没解释器就没意义
- ❌ **非计算类推理任务** — 文本分析/创意写作/情感理解等不适合
- ❌ **模型代码生成能力差的场景** — 如果模型写出的代码经常有语法错误
- ❌ **简单的四则运算** — CoT 就能搞定的小计算没必要上 PAL
- ❌ **安全性要求极高的环境** — 代码执行带来安全风险（需要沙箱）

---

## 4. PAL vs. CoT 本质区别

| | CoT | PAL |
|--|-----|-----|
| 推理媒介 | 自然语言 | 代码（Python 等） |
| 计算执行者 | LLM 自己（容易算错） | 程序解释器（不会算错） |
| 可靠性 | 取决于模型数学能力 | 取决于代码正确性 |
| 适用领域 | 一般推理 | 数学/日期/结构化计算 |
| 执行依赖 | 无 | 需要代码解释器 |
| Token 开销 | 中 | 中（代码通常比自然语言推理更简洁） |

## 5. 中文提示词模板

### 模板：PAL 代码生成 Prompt

```markdown
请通过编写 Python 代码来解决以下问题。

## 要求
1. 编写完整的、可直接执行的 Python 代码
2. 代码中包含清晰的注释说明每一步
3. 使用 print() 输出最终答案
4. 不要省略任何导入语句

## 问题
{问题描述}

## 代码
```python
# 请在此处编写代码
```
```

**填空示范——日期计算：**
```markdown
请通过编写 Python 代码来解决以下问题。

## 问题
一个产品于 2024 年 3 月 15 日上架，
至今（2026 年 5 月 14 日）已经上线了多少天？
如果是整年数，是多少年零多少天？

## 代码
（模型生成 Python 代码 → 交由解释器执行 → 得到精确结果）
```

**PAL 的关键是 prompt 让模型生成代码，然后由外部解释器执行——不是让模型"假装执行"。**

## 6. OpenClaw 使用方式

### 配置方案：PAL 增强型 Agent（带代码执行）

```
┌───────────────────────────────────────────────────┐
│              PAL-Enhanced Agent                    │
├───────────────────────────────────────────────────┤
│ System Prompt:                                    │
│   你是一个可以通过编写代码来解决问题的助手。          │
│   当涉及数学计算、日期运算、数据处理等问题时，       │
│   请编写 Python 代码来解决。                       │
│                                                   │
│ User Message:                                      │
│   {用户的问题}                                     │
│                                                   │
│ ↓ Agent 输出 Python 代码                           │
│                                                   │
│ ↓ 代码交由沙箱解释器执行                            │
│   (ast.parse 检查 → 安全执行 → 结果捕获)            │
│                                                   │
│ ↓ 将执行结果返回给用户                              │
└───────────────────────────────────────────────────┘
```

**安全的代码执行管道：**
```
1. 代码生成（LLM 输出 Python 代码）
2. 语法检查（ast.parse() 验证合法性）
3. 沙箱执行（限制：无网络访问、超时 5 秒、内存限制）
4. 结果校验（输出是否在合理范围内？NaN/Inf/异常值检测）
5. 兜底：代码执行失败时，回退到标准 CoT 自然语言推理
```

---

## 7. 单 Agent 适配度

# ★★★★☆ (4/5)

**原因：**
- PAL 模式可以在单 Agent 中实现：生成代码 → 传给执行器 → 返回结果
- 但需要额外的代码执行基础设施（沙箱/解释器）
- **如果没有代码执行环境，PAL 无法工作**

---

## 8. 多 Agent 适配度

# ★★★☆☆ (3/5)

**原因：**
- PAL 通常是单个 Agent 内部的增强模式（代码生成 + 执行）
- 在多 Agent 场景中，可以设一个专门的"计算 Agent"负责 PAL
- 但 PAL 本身不像 Chaining 或 ReAct 那样天然需要多 Agent

---

## 9. 常见失败

| # | 失败模式 | 典型表现 | 根本原因 |
|---|----------|----------|----------|
| 1 | **生成的代码有 Bug** | 语法错误或逻辑错误，执行失败或结果错误 | 模型的代码生成能力参差不齐 |
| 2 | **代码安全问题** | 生成的代码试图访问文件系统/网络/环境变量 | 需要沙箱隔离执行 |
| 3 | **执行超时** | 代码陷入死循环或大量计算 | 需要超时控制（建议 5-10 秒） |
| 4 | **没有执行环境** | 生成了好代码但没有地方跑 | PAL 的前置依赖：必须有代码解释器 |
| 5 | **用于非计算任务** | 让 PAL 写散文/做情感分析 | PAL 只适合需要精确计算的场景 |
| 6 | **结果不合理但格式合法** | 代码跑了但结果是 -9999 之类的异常值 | 需要结果合理性校验 |

## 10. 修正提示

### 修正：PAL 代码执行失败 → 沙箱 + 超时 + 兜底

**❌ 错误：** 模型生成了有语法错误的代码，exec() 直接报错

**✅ 修正——安全的代码执行管道：**
```
1. 代码生成（LLM 输出）
2. 语法检查（ast.parse() 验证 Python 合法性）
3. 沙箱执行（限制：无网络访问、超时 5 秒、内存限制）
4. 结果校验（输出是否在合理范围内？NaN/Inf/异常值检测）
5. 兜底方案：代码执行失败时，回退到标准 CoT 自然语言推理

if code_execution_failed:
    fallback_to_cot_reasoning(question)
```

## 11. 示例

### 场景：周报数据精确复核

**需求：** 复核周报中的复合指标计算是否正确，例如：
- 加权平均毛利率 = Σ(各SKU销售额 × 各SKU毛利率) / 总销售额
- 同比增长率 = (本期 - 去年同期) / 去年同期 × 100%

**PAL 应用：**
```python
# 由模型生成并由解释器执行的代码
sku_data = [
    {"name": "积木机械组", "sales": 45000, "margin": 0.32},
    {"name": "遥控赛车", "sales": 12800, "margin": 0.28},
    {"name": "慢回弹捏捏乐", "sales": 67200, "margin": 0.45},
    # ... 更多 SKU
]

total_sales = sum(sku["sales"] for sku in sku_data)
weighted_margin = sum(sku["sales"] * sku["margin"] for sku in sku_data) / total_sales

print(f"总销售额: {total_sales:.2f}")
print(f"加权平均毛利率: {weighted_margin*100:.2f}%")
```

**执行输出：** `总销售额: 125000.00` / `加权平均毛利率: 38.88%`

**vs CoT：** 模型用自然心算："大概... 39% 左右？" → PAL 给出精确值且过程可审计。

## 12. 与其他技术的组合方式

| 组合 | 方式 | 效果 |
|------|------|------|
| **PAL + CoT** | PAL 为主路径，CoT 为兜底（代码执行失败时回退） | **推荐默认组合**——保证可用性 |
| **PAL + Self-Consistency** | 多次生成代码 + 执行，取多数结果 | 对极高精度需求的计算任务 |
| **PAL + Prompt Chaining** | Chaining 中的"计算步骤"使用 PAL | 数据分析 pipeline 中的精确计算环节 |

**PAL 的定位：CoT 的"精确计算升级版"。** 当 CoT 的自然语言推理在计算上不够可靠时，PAL 是自然的下一步。
