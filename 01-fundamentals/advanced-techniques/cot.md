# Chain-of-Thought (CoT) — 思维链

> 🟢 **立即掌握** | DAIR.AI Advanced Prompting #1 | [返回总览](../dair-ai-advanced-prompting.md)

---

## 1. 一句话解释

**不直接要答案，而是让模型把推理过程一步一步写出来再得出结论。**

```
问题：小明有 10 个苹果，给了邻居 2 个，又给了修理工 2 个，
       然后又买了 5 个，吃了 1 个。还剩几个？

❌ Zero-Shot 直接答：11 个（算错了）

✅ CoT 让它想：
   第一步：开始有 10 个苹果
   第二步：给了邻居 2 个 + 修理工 2 个 = 给了 4 个，剩 6 个
   第三步：又买了 5 个，现在有 6 + 5 = 11 个
   第四步：吃了 1 个，最后剩 11 - 1 = 10 个
   答案：10 个 ✅
```

---

## 2. 适合什么时候用

- ✅ **多步数学运算** — 加减乘除、百分比、比例计算
- ✅ **逻辑推理题** — 年龄问题、追击问题、排列组合
- ✅ **数据分析与解读** — 让 AI 展示数据如何导出结论
- ✅ **因果分析** — "为什么 A 导致了 B？"
- ✅ **需要可追溯推理过程的任何场景**
- ✅ **周报异常检测** — 判品类状态并给出归因理由

---

## 3. 不适合什么时候用

- ❌ **简单分类/情感分析** — Zero-Shot 或 Few-Shot 足够，CoT 浪费 token
- ❌ **创意写作/开放生成** — 过度约束推理限制创造力
- ❌ **实时对话/聊天** — 用户不想等模型"想半天"
- ❌ **小模型（< 7B 参数）** — CoT 是涌现能力，小模型不具备
- ❌ **只需要快速粗略答案的场景** — 详细推理过程在这里是噪音

---

## 4. 三种变体

| 变体 | 方法 | 何时用 | 复杂度 |
|------|------|--------|--------|
| **Standard CoT** | Few-Shot + 手写推理链示例 | 有现成好范例时 | 中 |
| **Zero-Shot CoT** | 只加一句"让我们一步步思考" | 没时间写范例时 | ⭐ 最低 |
| **Auto-CoT** | 自动生成推理链（Zhang et al. 2022） | 需批量处理大量问题时 | 高（需编程） |

**🔑 Zero-Shot CoT 的魔法咒语：**

```
"让我们一步一步地思考。" 或 "Let's think step by step."
```

> Kojima et al. (2022)：就这一句话，大模型数学推理准确率大幅提升。这是性价比最高的高级技巧，没有之一。

**为什么有效？**
- **涌现能力（Emergent Ability）：** 只有足够大的模型才具备 CoT 能力
- **显式推理链：** 把隐式的"直觉计算"变成可追踪的步骤

## 5. 中文提示词模板

### 模板 A：Zero-Shot CoT 快速推理 ⭐ 日常首选

> **推荐等级：** ⭐⭐⭐⭐⭐

```markdown
{问题描述}

请一步一步地思考，并给出最终答案。
```

**填空示范——周报数据核查：**
```markdown
本周积木玩具销量 1,250 件，环比上周增长 15.2%。
上周积木玩具销量为 1,085 件。
请问环比增长率计算是否正确？如果不正确，正确值是多少？

请一步一步地思考，并给出最终答案。
```

**变体——加强版（要求更详细的推理）：**
```markdown
{问题描述}

请按以下步骤进行分析：
1. 明确已知条件
2. 确定计算方法
3. 逐步执行计算
4. 验证结果的合理性
5. 给出最终结论
```

### 模板 B：Few-Shot CoT 推理示范模板

```markdown
{任务描述}

示例 1：
{问题 1}
思考过程：{完整的推理步骤 1}
答案：{答案 1}

示例 2：
{问题 2}
思考过程：{完整的推理步骤 2}
答案：{答案 2}

{目标问题}
思考过程：
答案：
```

**填空示范——销售状态判定：**
```markdown
根据销量和环比变化率，判断品类的周表现状态。

示例 1：
品类：积木玩具 | 销量: 1200 | 环比: +15%
思考过程：销量超过 500 且环比增长超过 10%，属于高速增长区间，
符合"增长强劲"的标准。
答案：增长强劲 📈

示例 2：
品类：遥控赛车 | 销量: 85 | 环比: -32%
思考过程：销量低于 100 且环比下降超过 20%，双重预警信号，
符合"下滑严重"的标准。
答案：下滑严重 🔴

待判定：
品类：慢回弹捏捏乐 | 销量: 2100 | 环比: +8.3%
思考过程：
答案：
```

## 6. OpenClaw 使用方式

### 配置方案：CoT Agent（单 Agent 推理增强）

适用于：需要可靠推理的单 Agent 场景（数据分析、逻辑判断等）。

```
┌─────────────────────────────────────────────┐
│         CoT-Enhanced Agent                  │
├─────────────────────────────────────────────┤
│ System Prompt:                              │
│   你是一个{角色}。                           │
│   你的任务是{任务定义}。                      │
│                                             │
│   【重要】回答前必须逐步展示推理过程：        │
│   1. 列出已知条件                            │
│   2. 说明分析方法                            │
│   3. 逐步执行推理                            │
│   4. 得出结论                                │
│                                             │
│ User Message:                               │
│   {用户的原始输入}                           │
└─────────────────────────────────────────────┘
```

**效果：** 相比普通 Zero-Shot Agent，数学/逻辑类任务准确率大幅提升，token 开销增加约 2-3x。

**System Prompt 适配：** ✅ CoT 指令（如"逐步思考"）非常适合放入 system prompt；Few-Shot CoT 示例放 user message。

---

## 7. 单 Agent 适配度

# ★★★★★ (5/5)

**原因：**
- **Zero-Shot CoT 是单 Agent 最大的免费升级**——只加一句话就能显著提升推理质量
- CoT 的推理增强可以直接嵌入 System Prompt，无需额外架构
- **这是你日常使用 AI 时收益最高的技术**

---

## 8. 多 Agent 适配度

# ★★★★☆ (4/5)

**原因：**
- CoT 可以作为每个 Agent 内部的推理增强手段
- 在 Prompt Chaining pipeline 中，分析类步骤通常都会加 CoT
- 与 Self-Consistency 组合可用多 Agent 并行推理 + 投票

---

## 9. 常见失败

| # | 失败模式 | 典型表现 | 根本原因 |
|---|----------|----------|----------|
| 1 | **CoT 用于简单任务** | 分类任务也输出一大段推理，浪费 token 且速度慢 | 不是所有任务都需要推理 |
| 2 | **CoT 在小模型上无效** | 加了"让我们一步步思考"后更差 | CoT 是涌现能力，需 7B+ 参数模型 |
| 3 | **Zero-Shot CoT 推理链太简略** | 模型只给两行就跳到结论 | 需要加强版 prompt 要求详细步骤 |
| 4 | **Auto-CoT 生成的示例质量差** | 自动生成的推理链本身就有错 | Auto-CoT 取决于模型能力和问题分布 |

---

## 10. 修正提示

### 修正 1：CoT 用于简单任务 → 回退到 Basic Prompting

```
这个任务需要多步推理吗？
□ 是（涉及数学计算、逻辑判断、因果分析）→ 用 CoT
□ 否（分类/提取/改写/翻译/格式转换）→ 用 Basic Prompting 即可
```
**黄金法则：能用简单方法解决的问题，不要用复杂方法。**

### 修正 2：CoT 推理链太简略 → 加强版 CoT Prompt

```markdown
请对以下问题进行深度分析：

【问题】{问题内容}

请严格按照以下框架回答：

**第一步：信息提取**
列出题目中所有的已知条件和数值。

**第二步：分析思路**
说明你打算用什么方法解决这个问题，以及为什么选这个方法。

**第三步：逐步计算/推理**
一步步展示每一步的操作和中间结果。

**第四步：答案验证**
检查你的答案是否符合常理（如数值范围、单位是否合理等）。

**第五步：最终答案**
{
  "answer": "...",
  "confidence": "高/中/低",
  "reasoning_summary": "一句话总结推理要点"
}
```

## 11. 示例

### 场景：周报异常分析中的 CoT 应用

**原始需求：** "不仅帮我判品类卖得好不好，还帮我写出有说服力的分析理由"

**CoT 分析 Prompt（核心部分）：**

```markdown
你是一个资深的玩具品类运营分析师。

## 分析框架

对每个品类，你必须按照以下步骤逐步推理：

### Step A：状态判定
基于以下规则判断品类状态：
- 📈 增长强劲：销量 > 500 且 环比 > +10%
- 📊 稳步增长：销量 > 300 或 环比在 0%~+10%
- ➡️ 平稳：环比在 -10%~+10%
- ⚠️ 预警：环比 < -10% 但销量 > 100
- 🔴 下滑严重：环比 < -20% 或 销量 < 50

### Step B：归因推理
对于被标记为异常的品类，必须进行归因分析：
- 📈 增长强劲：是否有促销？季节性？爆款拉动？同比趋势？
- 🔴 下滑严重：是否缺货？竞品冲击？淡季？差评激增？

### Step C：行动建议
针对每个异常品类，给出 1-2 条本周可执行的行动建议。

## 输出要求
对每个品类，严格按以下格式输出：
### {品类名称} [{状态 emoji} {状态名}]
**状态判定：** {逐步推理过程}
**归因分析：** {如果有异常，逐步分析原因}
**行动建议：** {1-2 条具体可执行的建议}
```

**完整 Pipeline 中 CoT 的角色：** 数据准备(Python) → **CoT 异常分析(AI 核心)** → 报告整合(可选)

## 12. 与其他技术的组合方式

| 组合 | 方式 | 效果 |
|------|------|------|
| **CoT + Self-Consistency** | 先用 CoT 推理，再用 SC 多票投票 | 大幅降低错误率，适合关键决策 |
| **CoT + Prompt Chaining** | Chaining 的某个/多个步骤内部使用 CoT | 最常用的组合——pipeline 中嵌入推理 |
| **CoT + Generated Knowledge** | 先 GK 补充背景知识，再 CoT 推理 | 解决"模型不懂领域"的问题 |
| **CoT + PAL** | CoT 作为兜底，PAL 作为精确计算主路径 | PAL 失败时自动回退到 CoT |
