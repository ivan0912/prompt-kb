## 1. 模板目标

本模板解决以下问题：

| # | 问题 | 说明 |
|---|------|------|
| 1 | 同一个视频需求需要在多个平台测试 | 一份通用视频提示词无法在 Runway / Pika / Kling / Luma / Sora / 豆包 / 即梦上都生效 |
| 2 | 不同视频平台的提示词写法差异大 | 有的用自然语言详细描述，有的偏简洁短句，有的支持首尾帧控制，有的支持分镜结构 |
| 3 | 视频平台参数容易被误用 | 把 Sora 的长描述直接套到 Pika（只适合短视频），或把 Kling 的中文提示词格式套到需要英文的平台 |
| 4 | 平台切换时丢失视频核心信息 | 改写过程中只改语言或格式，丢了主体/场景/动作/镜头运动/时间顺序/节奏 |
| 5 | 不知道各平台是否支持负面提示词 | 有的平台有独立负面字段，有的只能融入正向描述，有的完全不支持 |
| 6 | 不知道各平台是否支持首帧/末帧/参考图 | 图生视频平台和纯文生视频平台的能力边界不同 |

**核心定位**：T-VIDEO-002 不是独立的视频提示词规范，而是 T-VIDEO-001 的**平台适配层**。它保留 T-VIDEO-001 定义的 20 维度核心结构（特别是运动层：镜头运动、时间顺序/分镜、节奏），根据不同平台特点调整表达方式。

### 本模板不解决的问题

| # | 不解决 | 原因 |
|---|--------|------|
| 1 | 实时平台参数查询 | 平台参数随版本变化频繁，本模板仅提供通用适配原则 |
| 2 | 保证跨平台生成效果一致 | 不同平台的底层模型不同，同样的提示词必然产生不同结果 |
| 3 | 替代平台官方文档 | 具体能力以各平台当前官方说明为准 |
| 4 | 处理高风险 / 侵权内容 | 真实人物还原、商标侵权、敏感内容等不在本模板覆盖范围 |
| 5 | 替代具体视频案例 | CS-VIDEO-001 等案例提供完整实战样例，本模板提供通用适配方法 |

## 2. 适用范围

### 2.1 适用

| # | 场景 | 说明 |
|---|------|------|
| 1 | 已有通用视频提示词，需要改写到不同平台 | 从一份通用提示词出发，生成 Runway / Pika / Kling / Luma / Sora / 豆包 / 即梦等平台版本 |
| 2 | 同一个视频需求需要在多个平台测试 | 横向对比不同视频平台的生成效果 |
| 3 | 需要比较不同平台对同一视频需求的还原度 | 保持视频核心信息（主体+场景+动作+镜头运动+时间顺序）一致，仅调整平台表达方式 |
| 4 | 需要生成中文和英文视频提示词 | 中文 → 豆包 / 即梦 / Kling；英文 → Runway / Pika / Luma / Sora |
| 5 | 需要为视频案例生成平台适配版本 | 如 CS-VIDEO-001 可经本模板生成各平台完整适配版本 |
| 6 | 需要避免平台参数误用 | 不写死版本号、不写死实时参数、不跨平台套用格式 |

### 2.2 不适用

| # | 场景 | 原因 |
|---|------|------|
| 1 | 精确影视级分镜制作 | 需要专业影视制作工具和流程，超出 AI 视频生成范围 |
| 2 | 高风险视频生成 | 涉及真实人物还原、深度伪造、侵权、敏感内容 |
| 3 | 实时平台参数查询 | 参数随版本更新而变，请查阅各平台最新官方文档 |
| 4 | 违法、侵权或敏感内容生成 | 本模板不支持此类任务 |
| 5 | 音频同步 / 对口型 / 精确音乐卡点 | 大多数视频生成平台尚不支持精确音频同步 |

### 通用视频提示词

## 5. 平台适配总原则

在改写为各平台版本之前，必须先确认以下原则：

| # | 原则 | 说明 |
|---|------|------|
| 1 | 先保留视频核心信息，再做平台改写 | 主体、场景、动作、镜头运动、时间顺序、节奏不能丢 |
| 2 | 风格、光线、色彩、材质要保持连续 | 这些视觉层元素在所有平台版本中应保持一致方向 |
| 3 | 首帧和末帧要根据平台能力决定是否显式描述 | 支持图生视频的平台应明确首帧用途；不支持的平台用文字描述起始/结束画面 |
| 4 | 负面限制要根据平台支持方式调整 | 有独立负面字段→填入；不支持→融入自然语言；完全不支持→强调正向替代 |
| 5 | 不同平台不要强行使用同一种格式 | Sora 用长段叙事；Pika 用简洁短句；Kling 用时间顺序分段 |
| 6 | 不写死平台版本号 | 如示例中出现版本信息，必须标注"以当前平台文档为准" |
| 7 | 不写死实时平台参数 | 参数仅作为字段名或建议方向，不给硬编码数值 |
| 8 | 平台参数仅作为字段或方向，不作为硬编码要求 | 如需提及参数，使用 `[参数值]` 占位符并标注"以平台文档为准" |
| 9 | 不支持独立负面提示词的平台，应把限制写进自然语言 | 例如将"no text, no watermark"改为"画面干净，无文字无水印" |
| 10 | 有参考图 / 首帧 / 末帧时，必须说明用途 | 作为风格参考？作为首帧输入（Image-to-Video）？作为末帧约束？ |
| 11 | 动作复杂度要与平台能力匹配 | 不要给 Pika 写 10 个连续动作的复杂分镜；不要给 Sora 写只有 1 个静态动作的过简提示词 |
| 12 | 高价值视频任务需要人工确认 | 动作合理性、镜头运动可行性、时长匹配、风险项（文字渲染/物理模拟/人物一致性） |

## 6. 平台类型分类

按**平台能力类型**分类，而非仅按平台名称罗列。同一平台可能同时属于多种类型。

| 平台类型 | 典型平台 | 适合任务 | 提示词重点 | 注意事项 |
|----------|----------|----------|-----------|----------|
| **① 自然语言视频生成型** | Sora、Runway Gen-α | 复杂场景、多镜头叙事、电影感短片 | 完整自然语言描述、故事化叙述、时间线清晰 | 可以写得较详细，但要注意动作逻辑自洽 |
| **② 图生视频 / 首帧驱动型** | Runway（图生模式）、Kling、可灵 | 基于静态图生成动态效果、产品动效 | 明确起始画面 + 动作描述 + 运动幅度 | 必须说明首帧图的用途和期望的运动方向 |
| **③ 首尾帧控制型** | Kling（首尾帧模式）、Luma、Runway（部分模式） | 需要精确控制起始和结束状态的视频 | 首帧描述 + 末帧描述 + 过渡过程 | 两端画面的一致性和过渡的自然性是关键 |
| **④ 分镜 / 多镜头结构型** | Sora、可灵（较长视频）、Runway（多片段拼接） | 多镜头叙事、转场丰富、情节驱动的视频 | 分镜头描述、每个镜头的画面+动作+时长+转场 | 注意镜头间的连贯性，避免跳切突兀 |
| **⑤ 产品展示 / 广告风格型** | Kling、可灵、豆包视频、即梦 | 产品广告、电商展示、品牌宣传 | 主体突出 + 光影质感 + 简洁动作 + 画面稳定性高 | 强调产品细节、材质表现和品牌一致性 |
| **⑥ 社交媒体短视频型** | Pika、豆包视频、即梦 | 社交配图、短视频封面、快节奏内容 | 简洁抓眼球 + 动作明确 + 时长短（通常 3-5s） | 避免复杂分镜，一个核心动作即可出彩 |
| **⑦ 通用模型集合型** | Hugging Face 开源模型、自部署模型 | 技术验证、定制需求、研究用途 | 需先确认具体模型的提示词格式和能力边界 | 差异极大，必须查看具体模型的 Model Card |

## 7. Runway 适配规则

### 7.1 平台特点

Runway 更适合视觉表达清晰、镜头运动明确、风格可控的视频生成。支持文本生成视频（Text-to-Video）和图像生成视频（Image-to-Video）两种模式。对自然语言描述理解较好，尤其擅长电影感和风格化表达。

### 7.2 适配重点

| 要点 | 说明 |
|------|------|
| **语言** | 中英文均可，英文通常更稳定 |
| **结构** | 使用清晰的自然语言段落，明确主体→动作→环境→镜头运动 |
| **镜头运动** | Runway 对镜头运动指令敏感度高——推/拉/摇/移/环绕等关键词有效 |
| **首帧模式** | 如使用 Image-to-Video，必须在提示词中明确"基于首帧图，[动作描述]" |
| **时长** | 通常支持较短时长（数秒到十数秒级别），具体以平台当前限制为准 |
| **负面提示词** | 取决于界面是否提供负面字段；如没有，将限制融入正向描述 |
| **风格** | 可加入风格修饰词（cinematic, film grain, shallow depth of field 等） |

### 7.3 输出结构

```
### Runway 提示词

[自然语言视频提示词，包含：
 - 主体及其外观
 - 所在场景和环境
 - 核心动作（1-3个关键动作）
 - 镜头运动方式
 - 时间顺序（开头→中段→结尾）
 - 风格/光线/色彩
 - 限制条件（如不支持独立负面字段）]

### 镜头与动作说明

[动作分解：每个动作的主体、方向、幅度、持续时间]
[镜头运动：运镜方式、速度、起止点]
[节奏：整体快慢、有无变速需求]

### 首帧说明（如使用 Image-to-Video）

[首帧图用途：作为起始画面 / 风格参考 / 构图参考]
[期望基于首帧产生的运动方向和幅度]

### 负面限制

[自然语言形式的不需要的内容。
 如平台支持独立负面字段，可单独列出；
 如不支持，已融入上方 Runway 提示词中]

### 注意事项

- Runway 的具体参数（运动强度 Motion Brush 数值、相机控制选项等）以当前平台界面和文档为准；
- 版本和功能随平台更新可能变化；
- Image-to-Video 模式的提示词侧重"从这幅图出发发生什么"；
- Text-to-Video 模式的提示词侧重"从头开始构建整个场景"。
```

## 8. Pika 适配规则

### 8.1 平台特点

Pika 更适合短视频、动态效果、社交媒体风格的视频生成。生成速度快，对文字驱动和简单动作响应良好。但运动幅度和时长有限制，不适合复杂多镜头叙事。

### 8.2 适配重点

| 要点 | 说明 |
|------|------|
| **语言** | 中英文均可，简洁表达效果好 |
| **结构** | 短句为主，一个核心动作 + 环境 + 结果即可 |
| **动作数量** | 建议 1-3 个动作，避免过长复杂的动作链 |
| **时长** | 通常较短（3-5s 左右），具体以平台当前限制为准 |
| **镜头运动** | 简单镜头运动即可（缩放/平移/固定），不需要复杂运镜设计 |
| **负面提示词** | 取决于平台界面；通常限制较少时融入正向描述即可 |
| **特色** | 对"修改"类操作支持较好（如"让图中的人眨眼""让水流动起来"） |

### 8.3 输出结构

```
### Pika 提示词

[简洁自然语言视频提示词，1-3 句话：
 - 主体 + 核心动作（1个主要动作优先）
 - 场景 + 简单环境描述
 - 运动方向/结果
 - 如有限制，融入句中]

### 动作重点

[列出 1-3 个动作重点，按优先级排序：
 1. [最主要动作] — [方向/幅度/结果]
 2. [次要动作] — [简要说明]
 3. [可选动作] — [简要说明]]

### 负面限制

[自然语言形式的限制条件。
 如平台支持独立负面字段则单独列出，
 否则已融入上方 Pika 提示词中]

### 注意事项

- Pika 适合轻量级视频任务（对应 T-VIDEO-001 的 L1-L3 或轻量 L4）；
- 避免写入过多动作或复杂分镜——超出平台能力范围会导致效果下降；
- 简洁 > 复杂：一句话说清楚"什么在怎么动"比写一段叙事更有效；
- 具体的时长上限、分辨率等以平台当前说明为准。
```

## 9. Kling / 可灵 适配规则

### 9.1 平台特点

Kling（国际版）和可灵（国内版）更适合较强运动表现、产品展示、人物或场景动态视频。支持较长时长、较好的运动控制和主体一致性。中文提示词在国际版同样可用，国内版对中文理解优秀。

### 9.2 适配重点

| 要点 | 说明 |
|------|------|
| **语言** | 中英文均可；国内版（可灵）中文提示词效果优秀；国际版（Kling）英文更稳定 |
| **结构** | 按时间顺序组织：开头 → 发展 → 结尾 |
| **动作** | 动作描述可以比较详细，平台对运动表现力支持较好 |
| **镜头运动** | 推/拉/摇/移/跟拍/环绕等均有效 |
| **主体一致性** | 如果视频中主体需要保持一致外观，应在提示词中反复强调 |
| **首尾帧** | 支持首尾帧控制模式，可用于精确控制起始和结束状态 |

## 16. 常见错误

| # | 错误 | 表现 | 修正建议 |
|---|------|------|----------|
| 1 | 把一个平台参数直接用于所有平台 | 把 Sora 的长段叙事直接复制给 Pika（Pika 只需要 1-3 句） | 根据各平台的适配规则（§7-§13）调整提示词长度和结构 |
| 2 | 写死平台版本号 | "Runway Gen-3 Alpha"、"Sora v2" 等硬编码在模板中 | 不写版本号；如必须举例，标注"版本仅为示例，以当前平台文档为准" |
| 3 | 写死实时参数 | "时长 10 秒"、"分辨率 1024×576"、"motion strength 5" 等硬编码 | 使用占位符 `[时长]` 或写"以平台当前设置为准" |
| 4 | 只改语言，不改结构 | 直接把中文翻译成英文就当作另一个平台版本 | 不同平台需要不同的结构（长度/格式/详细程度），不只是翻译 |
| 5 | 丢失动作 | 原始需求有 3 个动作，平台版本只写了 1 个 | 对照原始需求的动作清单逐条检查 |
| 6 | 丢失镜头运动 | 通用版本写了"缓慢推近 + 环绕半周"，平台版本只写了"拍摄产品" | 镜头运动是视频区别于图像的核心要素，不能省略 |
| 7 | 丢失时间顺序 | 通用版本有明确的"开头→中段→结尾"，平台版本变成一堆碎片描述 | 保持时间线结构（尤其是 Kling/可灵 和 Sora 版本） |
| 8 | 丢失负面限制 | 原始需求写了"不要文字不要 logo不要人物"，适配后只剩风格描述 | 每次改写后重新对照原始限制条件逐条检查 |
| 9 | 过度复杂分镜 | 给 Pika 写了 8 个镜头的分镜表 | 匹配平台能力：Pika 用 1-3 个动作；Sora 才用完整分镜 |
| 10 | 忽略首帧 / 末帧用途 | 上传了首帧图但没说"这是 I2V 的起始画面"还是"仅供参考风格" | 必须在提示词或说明中明确每张参考图的用途（T-CONFIG-006 §17） |
| 11 | 忽略主体一致性 | 多镜头视频里产品的颜色/形状在第 3 秒后变了 | 在提示词中反复强调主体的不变特征（尤其是 Kling/可灵的长视频） |
| 12 | 忽略画面稳定性 | 产品广告视频出现了明显的抖动或形变 | 在提示词中明确"画面稳定"或"steady camera"；在限制中加入"无明显抖动" |
| 13 | 忽略平台是否支持负面提示词 | 把 `no text, no watermark, blur, bad anatomy` 直接用于不支持负面的平台 | 查看平台能力后决定：支持→填入独立字段；不支持→融入正向描述 |
| 14 | 把图像提示词直接当视频提示词 | 把 CS-IMG-001 的图像提示词原封不动当作视频提示词使用 | 图像缺少动作/镜头运动/时间顺序/节奏——这些是视频必不可少的信息 |
| 15 | 参考图用途写得太模糊 | "参考附件图"——不知道该参考什么 | 明确写明：参考风格？参考构图？参考色彩？作为 I2V 首帧输入？ |

## 17. 与现有文件关系

### 17.1 与 T-VIDEO-001 的关系

T-VIDEO-001 定义视频提示词的 20 维度标准结构（目标层/主体层/视觉层/运动层/帧控制/限制层）、标准输入区/输出区、L1-L5 复杂度分级和核心公式（14 元素）。T-VIDEO-002 基于这 20 维度，根据不同平台类型的特点调整表达方式。**T-VIDEO-002 不重复定义 20 维度的规则，只关注"如何改写到具体平台"。**

### 17.2 与 video-prompt-quick-reference 的关系

quick-reference 是 T-VIDEO-001 的日常速查卡，提供 20 维度速查表、口语需求转写模板、分镜模板和 20 项验收清单。T-VIDEO-002 是对 quick-reference 中"平台适配"维度的展开——quick-reference 覆盖平台适配作为一个维度条目，T-VIDEO-002 把这一条展开为完整的 7 类平台 × 14 个输出模块的适配体系。

### 17.3 与 CS-VIDEO-001 的关系

CS-VIDEO-001 是首个视频提示词实战案例，其 §11 给出了 7 个平台的通用适配建议。T-VIDEO-002 将 CS-VIDEO-001 §11 的"平台适配建议表"扩展为完整的可复制模板，供后续所有视频任务复用。CS-VIDEO-001 可作为 TEST-VIDEO-002-001 的测试输入。

### 17.4 与 T-IMG-002 的关系

T-IMG-002 是图像提示词平台适配模板（6 个图像平台）。T-VIDEO-002 是其**同族视频版本**，继承了相同的设计理念（平台类型分类→各平台适配规则→多平台输出模板→检查清单），但在三个关键方面做了**视频特化扩展**：
- 新增**运动层维度**（动作/镜头运动/时间顺序/节奏）的跨平台保留检查
- 新增**帧控制维度**（首帧/末帧/画面稳定性/图生视频模式）的平台能力差异处理
- 新增**7 种平台类型分类**（vs T-IMG-002 按平台名称罗列），因为视频平台的能力分化比图像平台更大

### 17.5 与 T-CONFIG-005 格式和占位符的关系

T-CONFIG-005 §13 定义了视频提示词的格式描述规范（参数占位符/标准输入区），T-CONFIG-005 §15.5 定义了视频任务占位符库。T-VIDEO-002 的标准输入区（§4）和各平台输出结构中的占位符完全遵循 T-CONFIG-005 的中文方括号规范。

### 17.6 与 T-CONFIG-006 长上下文和参考资料的关系

T-CONFIG-006 §17 定义了图像/视频参考资料的处理规范（参考图的用途说明、来源标注等）。T-VIDEO-002 的"参考资料"输入区、"参考图用途说明"检查项（#16）和"首帧/末帧用途说明"检查项（#17）严格遵循 T-CONFIG-006 的规定。
